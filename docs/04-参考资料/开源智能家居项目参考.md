# 开源智能家居大模型项目参考

## 1. 结论

目前已经有与本项目相似的开源作品，但没有一个项目完全等同于：

```text
大语言模型 + RAG + 多 Agent + ESP32 + MQTT + Vue 前端
```

因此不建议从零开发，也不建议完整复制某一个项目。

推荐采用：

> **保留现有 `financial_rag` 的 RAG、Agent 和前端基础，参考开源项目的 ESP32、MQTT 和设备控制实现。**

## 2. 最接近的开源项目

### 2.1 proactive-home-agent

项目地址：

<https://github.com/berkyalkn/proactive-home-agent>

相关技术：

- ESP32 设备节点；
- MQTT 通信；
- Ollama 本地大模型；
- LangGraph Agent；
- ChromaDB 向量数据库；
- RAG 检索；
- 智能家居设备控制。

与本项目的相似点：

```text
ESP32 + MQTT + LLM + RAG + Agent
```

适合参考：

- ESP32 与后端如何通信；
- MQTT 主题如何设计；
- 传感器数据如何上传；
- 设备控制命令如何下发；
- Agent 如何调用设备能力。

不建议直接照搬：

- 完整复制项目架构；
- 直接复制不理解的 Agent 代码；
- 替换掉当前已有的 RAG 基座。

### 2.2 agentic-iot-local-llm

项目地址：

<https://github.com/aaryangupta/agentic-iot-local-llm>

相关技术：

- ESP32 固件；
- MQTT；
- Ollama；
- 本地大模型；
- 观察、推理、执行、记忆流程；


这个项目规模较小，适合先理解最基本的物联网 Agent 闭环。

### 2.3 Home LLM

项目地址：

<https://github.com/acon96/home-llm>

相关技术：

- Home Assistant；
- 本地大模型；
- 家居设备控制；
- MQTT 设备接入；
- 设备能力调用。

适合参考：

- 大模型如何获取设备列表；
- 大模型如何调用固定设备工具；
- 设备状态如何反馈给大模型；
- 设备能力如何限制控制范围。

它更偏向“Home Assistant + LLM”，不以多 Agent 和 RAG 为核心。

## 3. 不建议全部照搬的项目

### Home Assistant + ESPHome

Home Assistant 和 ESPHome 是非常成熟的智能家居基础设施，但完整引入会增加很多内容：

- Home Assistant 部署；
- ESPHome 配置；
- 设备发现；
- 自动化规则；
- 仪表盘配置；
- 平台适配和调试。

如果本项目重点是大模型、RAG 和多 Agent，第一阶段可以不引入 Home Assistant，直接使用：

```text
ESP32 → MQTT Broker → Python 后端
```

后续如果需要扩展真实家居设备，再考虑接入 Home Assistant。

## 4. 本项目的复用方案

### 4.1 继续使用现有项目

当前 `financial_rag` 已经可以继续保留：

```text
financial_rag/
├── RAG 文档处理
├── 文档切分
├── Embedding
├── 向量检索
├── LLM 调用
├── LangGraph 工作流
├── 多 Agent 流程
├── FastAPI 后端
└── Vue 前端
```

这些内容不需要重新开发。

### 4.2 只新增智能家居相关部分

需要新增或改造的内容：

```text
智能家居知识库
ESP32 MQTT 通信
read_sensors()
set_light()
set_fan()
设备状态缓存
设备能力白名单
安全规则检查
前端设备状态卡片
```

### 4.3 推荐的数据流

```text
DHT22 / BH1750 / PIR
          ↓
        ESP32
          ↓ Wi-Fi / MQTT
      Python 后端
          ↓
    大模型 + RAG + Agent
          ↓
     安全规则检查
          ↓
       MQTT 命令
          ↓
 LED / 5V 风扇 / 舵机
```

## 5. 与开源项目的关系

本项目不是简单复制开源代码，而是：

| 部分 | 来源或基础 |
|---|---|
| RAG 知识库 | 当前 `financial_rag` 基座 |
| 多 Agent 流程 | 当前 `financial_rag` 基座并做领域迁移 |
| Vue 前端 | 当前 `financial_rag` 前端并做页面改造 |
| MQTT 通信思路 | 参考 `proactive-home-agent`、`agentic-iot-local-llm` |
| 设备能力调用 | 参考 `Home LLM` |
| 多 Agent 工具协作 | 参考 `CrossKlaw` |
| ESP32 传感器与执行器 | 自己实现最小硬件闭环 |

## 6. 推荐的开发顺序

### 第一阶段：不接硬件

先使用模拟设备数据完成：

```text
自然语言提问
→ RAG 检索
→ Agent 分析
→ 返回设备控制计划
```

### 第二阶段：接入 MQTT

使用电脑上的 MQTT Broker，让后端先和模拟设备通信。

### 第三阶段：烧录 ESP32

用 Arduino IDE 给 ESP32 烧录程序，实现：

- 读取温湿度；
- 读取光照；
- 读取人体状态；
- 接收 LED/风扇控制命令；
- 上报设备状态。

### 第四阶段：完成答辩闭环

演示：

```text
用户说“我要睡觉了”
→ Agent 查询环境
→ RAG 查询睡眠规则
→ 生成设备动作
→ 安全检查
→ MQTT 下发命令
→ ESP32 控制灯和风扇
→ 前端显示执行结果
```

## 7. 最终建议

最适合本项目的组合是：

```text
现有 financial_rag
        +
proactive-home-agent 的 MQTT/ESP32 思路
        +
Home LLM 的设备工具设计
        +
自己的智能家居知识库和前端演示
```

不要从零搭建完整智能家居平台，也不要一开始接入十几个设备。

第一版只做：

```text
ESP32 + DHT22 + BH1750 + PIR + LED + 5V 小风扇
```

这样既能复用现有代码，也能形成自己的毕业设计工作量。

## 8. 使用开源项目的注意事项

1. 下载代码前查看项目许可证；
2. 论文中注明参考的项目和技术来源；
3. 不要直接复制项目 README 或整段代码；
4. 记录自己修改的模块和新增功能；
5. 不要把开源项目的密钥、配置文件或个人信息带入项目；
6. 停止维护的项目只用于参考，不作为核心依赖。
