# 智能家居极端触发与破坏风险清单

## 1. 风险范围

风险集中在自然语言控制、设备状态不一致、MQTT 通信异常、会话越权和硬件误接线。任何“模型说了算”的路径都不属于安全设计。

## 2. 高风险触发

| 风险 | 例子 | 必须的防护 |
|---|---|---|
| 任意设备控制 | 要求控制未注册设备 | 注册表和设备类型白名单 |
| 任意底层控制 | 要求发送 Topic 或 GPIO | 工具参数固定，底层信息不出现在模型上下文 |
| 越权控制 | 使用其他租户的 device_id | 认证、租户过滤和服务层校验 |
| 伪造成功 | 命令发布后直接回复已执行 | 等待匹配 ack，超时即失败 |
| 重放命令 | 重发旧 request_id | TTL + 幂等缓存 |
| 状态竞态 | 快速交替开关或场景重入 | 命令状态、串行化和幂等 |
| 离线误控 | 设备已掉线仍下发命令 | availability 和 online 检查 |
| MQTT 注入 | 构造任意 Topic 或恶意 JSON | 固定 Topic、结构化 schema、ACL |
| 提示词注入 | 文档要求绕过安全校验 | 文档仅作知识依据，工具层再次校验 |
| 高压误接 | 让 ESP32 控制 220V 设备 | 仅允许低压 LED/5V 风扇，硬件隔离 |

## 3. 测试清单

- 未注册设备、错误设备类型、离线设备；
- 非 `on/off` 状态、超长 request_id、过期命令；
- 重复 request_id、并发场景、ack 超时和否定 ack；
- 错误设备/房间的 ack、伪造 telemetry、Broker 断连和恢复；
- 跨租户访问、未登录调用和权限变更后的旧会话；
- Prompt 注入、任意 Topic/GPIO 请求和敏感信息回显；
- ESP32 电源不足、风扇启动干扰、传感器断线和 Wi-Fi 重连。

## 4. 最低防护基线

```text
用户/租户认证
  → 家居意图与工具白名单
  → 设备注册、类型、在线、动作、TTL 校验
  → request_id 幂等
  → MQTT ACL/QoS 1/结构化 JSON
  → device_id + request_id 匹配 ack
  → 审计、失败提示和人工复核入口
```

## 5. 日志要求

记录 interaction_id、request_id、租户、设备、动作、校验结果、阻断原因、适配器、ack 和时间戳。不得记录 MQTT 密码、TLS 私钥、完整敏感提示词或任意 GPIO/Topic 扩展内容。
