## 1 项目目标

小智 ESP32 通过设备端 MCP 和串口控制 STM32 智能家居模型，读取温度、湿度、相对光照及烟雾传感器原始值。STM32 负责采样、OLED 显示与执行器控制，保留机智云和离线语音链路。

当前烟雾需求是读出与 STM32 屏幕同源的 ADC 数值。没有浓度标定，不能把该值称为 ppm，也不能据此断言无烟或空气安全。光照同样未标定，不能称为实际 lux。

历史 RAG、Agent、网页控制台不属于当前交付。已授权的 DeepSeek 服务端语音网关是独立后续事项，不是当前串口链路的依赖。

## 5 接线与协议

### 固定硬件

STM32F103C8T6，64 KB Flash、20 KB RAM；Keil 目标 `SmartHome_STM32F103C8`。小智板型 `bread-compact-stm32-lcd`，ESP32-S3，当前构建保持 16MB Flash 和 128×160 显示配置。

| 线 | STM32 | ESP32 |
|---|---|---|
| 橙色 | PB11，USART3 RX | IO17，TX |
| 黄色 | PB10，USART3 TX | IO18，RX |
| 地线 | GND | GND |

板间通信固定 **9600 8N1**。USB 烧录命令中的 460800 是下载速率，不是板间通信速率。USART1 保留离线语音，USART2 保留机智云。

### 控制与遥测

控制帧仍为 `F4 06 命令 FB`。灯 01/02、风扇 03/04、窗户 05/06、手动/自动 07/08、门 09/0A、睡眠/离家 0B/0C、起床 0D。设备控制先发手动帧，发送成功后发动作帧；工具返回入队结果，不是实物执行 ACK。

环境约每秒采样并上报。v2 帧为 20 字节、小端整数：

| 位置 | 内容 |
|---|---|
| 0–3 | F4、08、版本 02、有效位 |
| 4–5 | 温度、湿度 |
| 6–7 | 相对光照 `4096 - ADC` |
| 8–9 | 烟雾 ADC 原始值 `Smoke` |
| 10–13 | 温湿度采样年龄 ms |
| 14–17 | ADC 采样年龄 ms |
| 18–19 | 字节 1–17 的 XOR、FB |

有效位 bit0 表示温湿度，bit1 表示光照和烟雾 ADC 共同有效。烟雾合法原始范围 0–4095，光照 1–4096；烟雾 0 是有效数值，不等于无烟。超过 3000ms、ADC 无效或旧 v1 缺少烟雾字段时，`smoke_raw=null`、`smoke_valid=false`。

**新 ESP32 兼容旧 STM32；旧 ESP32 不支持新 STM32 v2。** 因此先更新 ESP32，再更新 STM32。完整字段说明见[环境查询说明](02-技术方案/小智室内环境查询_2026-10-11.md)。

### 第三步 实物与语音验收

1. 在低压模型上开窗，待停止后说“进入睡眠模式”，确认灯关、风扇开、门执行关闭目标、窗户执行关闭目标；在 APP 选择睡眠也应关闭窗户。
2. 窗户已关闭时重复进入睡眠，不能继续转动；开到一半时进入睡眠，应转为关闭。
3. 说“我起床了”，核对实际 MCP 调用 `self.stm32.set_mode`、参数 `wakeup`、串口发送 `0x0D`，并确认灯开、风扇关、门执行打开目标，窗户不被打开。
4. 等待下一轮主循环后动作应保持；云端若只口头回应而未调用工具，应记录工具日志，不能视为控制已完成。

烟雾查询继续按以下步骤验收：

1. 两板运行新版后重启小智，重新建立设备连接和工具列表。
2. 让小智“读取当前烟雾传感器数值”，与 STM32 首页烟雾 ADC 比较。比较的是实时 `Smoke`，不是设置页的报警阈值 `Smoke_value`。
3. 保持环境稳定再问一次，确认每次读取新快照，语音说明是原始 ADC。无需制造烟雾进行测试。
4. 核对温度、湿度和光照查询仍可用，灯及其他控制功能无回归。
5. 在受控条件下停止回传，超过 3 秒应报告不可用，不能继续报旧烟雾值或编造 0。
6. 记录两板固件哈希、屏幕数值、小智回答、操作时间和结果；有差异再抓取串口接收与实际工具调用证据。
