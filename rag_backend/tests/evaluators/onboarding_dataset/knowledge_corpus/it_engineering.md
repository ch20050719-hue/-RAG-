# 研发与 IT 工程规范指南 (IT & Engineering Guidelines)
版本：v2026.2 | 适用对象：研发、测试、运维、算法及工程技术全体人员

## 第一章 IT 资产与网络权限
1. **办公设备申领**：
   - 入职首日凭入职工单到 IT 运维台领取统一配备的标准工作电脑（MacBook Pro 16寸 或 ThinkPad P系列移动工作站）；
   - 外接显示器、拓展坞及人体工学外设可由部门主管审批后通过 IT 资产申领单申请；
   - 员工应妥善保管设备，非自然折旧导致的硬件物理损坏需由个人承担 50% 维修费用，整机遗失按折旧价值赔付。
2. **内网与网络访问安全**：
   - 办公区无线网络统一连接 `Corp-Staff-Secure`，使用员工工号及企业密码通过 802.1X 协议认证，严禁私自搭建未经报备的 Wi-Fi 热点；
   - 居家或出差等远程办公必须使用公司统一配置的 GlobalProtect VPN，开启双因子认证（2FA/TOTP）；
   - 严禁在工作设备上运行未报备的远程控制软件或利用公司网络搭设未授权的公网代理。

## 第二章 代码托管与 Git 工作流规范
1. **仓库保护与分支策略**：
   - 主干分支 `main`（或 `master`）设为受保护分支，严禁直接 push，仅允许通过 Merge Request (MR) 合入；
   - 日常功能开发使用 `feature/JIRA-编号-简短描述` 分支；缺陷修复使用 `fix/JIRA-编号` 分支；紧急热修复使用 `hotfix/v版本号` 分支。
2. **提交信息规范 (Conventional Commits)**：
   - Commit Message 格式必须为 `<type>(<scope>): <subject>`，例如 `feat(auth): 新增双因子认证支持`；
   - 合法类型包括：`feat`（新特性）、`fix`（修缺陷）、`docs`（文档）、`refactor`（重构）、`perf`（性能优化）、`test`（增加测试）、`chore`（构建/依赖工程事务）。
3. **代码评审 (Code Review) 与 CI 门禁**：
   - 每个 MR 必须至少获得 2 位同组资深工程师的 `Approve` 评审通过；
   - CI 流水线门禁强制校验：
     - SonarQube 静态代码检查无新增 Blocker/Critical 级别漏洞；
     - 新增/修改代码的单元测试行覆盖率（Unit Test Coverage）不得低于 80%；
     - 代码重复率（Duplication Rate）必须低于 3%。

## 第三章 环境体系与数据访问权限
1. **四层研发环境分级**：
   - 开发环境 (DEV)：开发者本地或容器化集群，用于自测；
   - 测试环境 (TEST)：集成测试与自动化流水线运行环境；
   - 预发环境 (PRE)：与生产完全对齐的脱敏演练环境；
   - 生产环境 (PROD)：对外服务的核心线上集群。
2. **生产环境与数据库权限申请**：
   - 严禁普通研发人员直接登录生产服务器 SSH；
   - 生产数据库只读（Read-Only）权限须通过 JIRA 安全审计工单申请，经直属 Leader 与安全团队双重审批，审批时效通常为 4 个工作小时；
   - 单次只读权限有效期最长为 7 个自然日，到期由系统自动收回；
   - 生产环境严禁执行无 `WHERE` 条件的 `UPDATE/DELETE` 以及任何 `DROP/TRUNCATE` 操作。
3. **敏感凭据管理**：
   - 严禁将数据库账号密码、阿里云/AWS AccessKey、微信/支付宝秘钥明文提交至 Git 仓库中；
   - 密钥必须通过 Vault 或环境变量注入，CI 阶段集成 GitGuardian 密文扫描，一旦发现明文硬编码将阻断流水线并通报责任人。
