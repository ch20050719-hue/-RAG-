# 智能家居当前架构决策记录

> 状态：历史软件控制链路记录。当前项目不再维护 Python/RAG、Agent、后端或网页功能；硬件与项目范围以根目录约定和最新的[项目交接说明](智能家居项目交接说明.md)为准。本文仅作历史参考。

## 1. 当前有效事实

本项目只维护智能家居模块；Agent 编排、会话和权限作为通用基座保留，单房间家居主链路不依赖运行时动态检索。版本三硬件主控为 STM32F103C8T6，网络通信模块为 ESP8266，云平台为机智云。旧 ESP32 目录只作为历史协议参考，不作为当前硬件实现依据。

当前检测对象：温度、湿度、烟雾、火焰、有人。当前执行对象：低压 LED、5V 风扇、喷淋水泵模拟器、有源蜂鸣器、舵机门锁。系统不包含光照、窗户、28BYJ、BH1750、DHT22、SNR9902 或 CO2 领域能力。

## 2. 软件分层

```text
前端控制台 / APP / 按键 / 密码 / IC 卡
                 ↓
FastAPI Home API / Agent 固定工具
                 ↓
DeviceService + EnvironmentMonitor + 安全校验
                 ↓
SimulatedDeviceAdapter 或受控 MQTT/Gizwits Adapter
                 ↓
ESP8266 → STM32 → 低压传感器和执行器
```

`app/home_automation/device_tools.py` 是 Agent 的唯一设备工具入口。底层 GPIO、任意 MQTT Topic 和机智云数据点不得进入提示词、工具参数或前端。

## 3. 模式关系

版本三只保留一个设备主控制模式：

| 模式 | 行为 |
|---|---|
| `manual` 手动 | 按键或 APP 的明确指令控制设备；环境读数只展示和报警，不自动改设备 |
| `automatic` 自动 | 环境规则允许固定联动：温度/烟雾→风扇+蜂鸣器，火焰→水泵+蜂鸣器，有人→LED |

正常、睡眠、离家是固定场景预设，不是设备主控制模式。场景通过固定工具/API 执行：正常不改变设备状态；睡眠关闭 LED 并尝试反锁；离家关闭 LED/风扇并尝试锁门。场景与手动/自动模式解耦，门锁动作仍必须进入专用命令链路。

场景还决定人工控制工具的白名单，后端 `scene_policy.py` 强制执行，前端隐藏按钮不构成安全边界：

| 场景 | 允许的人工执行工具 | 始终保留的能力 |
|---|---|---|
| 正常 | LED、风扇、水泵、蜂鸣器、阈值、手动/自动模式、门锁 | 环境读取、设备状态、自动安全联动、场景切换 |
| 睡眠 | LED、风扇、蜂鸣器、门锁 | 环境读取、设备状态、自动安全联动、场景切换 |
| 离家 | 水泵、蜂鸣器、门锁 | 环境读取、设备状态、自动安全联动、场景切换 |

密码、IC 卡和 APP 都可以作为各场景的门锁认证来源，但解锁、开门和解除反锁仍必须通过认证参数与门锁专用安全服务；自动安全联动使用独立的 `automatic` 来源，不会被人工工具白名单误拦截。

## 4. 安全决策

- 所有设备控制都要校验注册、设备类型、在线状态、命令状态和过期时间；
- 普通开关接口只允许 LED 和风扇；水泵、蜂鸣器和门锁必须走固定专用入口；
- `request_id` 保证命令幂等，MQTT ack 必须匹配房间、设备、动作和请求；
- 解锁必须满足密码、IC 卡或 APP 的认证结果，并保留审计信息；
- 只允许低压桌面原型，禁止接入 220V 市电、真实住宅门锁和任意外部执行器。
