## 2026-10-11 聆听超时

小智应用增加无人说话自动待机：唤醒后或回复播放完毕后，连续 8 秒未检测到语音，关闭音频会话并恢复唤醒词待机。8 秒内继续说话可保持连续对话；此判断针对语音活动，不要求是设备控制指令。手动按键录音不受这个计时限制。

收到语音活动或非空识别文本后，暂停空闲计时，等待服务端回复；回复开始和播放期间不触发 8 秒超时。`tts stop` 后仍须等待本地播放队列排空。若声音被误检或服务端没有回复，另有 60 秒响应等待上限，防止永久聆听；持续说话会刷新该上限。无 VAD 的音频引擎不启用本功能，当前 S3 配置启用了音频处理器。

实现位于小智应用 `main/application.cc`、`main/application.h`、`main/conversation_timeout.h`，参数为 `kSilenceUs` 和 `kResponseWaitUs`。复用已有状态机、VAD、播放排空检测和音频通道关闭接口，不修改 STM32 协议。参考[上游无人说话超时讨论](https://github.com/78/xiaozhi-esp32/discussions/1547)与[官方语音协议](https://github.com/78/xiaozhi-esp32/blob/main/docs/websocket_zh.md)；本实现额外区分等待回复和本地播放尾音。

`tests/run-conversation-timeout-tests.ps1` 的 47 项主机检查通过，包含 8 秒边界、长句、慢识别/回复、60 秒保护、尾音播放、实时对话 VAD 边沿、重新唤醒和手动模式禁用。实际 UART 驱动 63 项、真实 STM32 解析器集成 185 项回归通过。原构建工具 71 项中 66 项通过、5 项仍因 Windows 临时目录清理失败；未测覆盖率，未烧录。

因此工作副本 `stm32/程序` 配置为 C8，64 KB Flash、20 KB RAM，目标名 `SmartHome_STM32F103C8`。

## 接线与串口

| ESP32 | STM32F103C8T6 |
|---|---|
| IO17 TX | PB11 / USART3_RX |
| IO18 RX | PB10 / USART3_TX |
| GND | GND |

9600、8N1、3.3V 逻辑。USART1 PA9/PA10 保留离线语音入口，USART2 PA2/PA3 保留机智云入口。
不同串口输入使用独立帧解析状态，不把来自两条串口的半包拼成控制帧。
控制命令仍无执行确认。2026-10-11 新增独立环境遥测和查询工具，返回温湿度、相对光照及有效性，不作为执行器 ACK，见[环境查询说明](小智室内环境查询_2026-10-11.md)。

## 命令与模式

帧为四个原始字节 `F4 06 命令 FB`，串口助手应选择 HEX 发送。

| 功能 | 命令 |
|---|---|
| 灯开 / 关 | 01 / 02 |
| 风扇开 / 关 | 03 / 04 |
| 窗户开 / 关 | 05 / 06 |
| 手动 / 自动 | 07 / 08 |
| 门开 / 关 | 09 / 0A |
| 睡眠 / 离家 | 0B / 0C |

ESP32 单设备控制先发手动命令，等待 350ms，再发动作；模式工具只发该模式命令。
STM32 从自动切手动时会关灯、关风扇、请求关窗并停蜂鸣器，随后执行指定单设备动作。
睡眠：手动、风扇开、灯关、门关；离家：手动、风扇关、灯关、门关；两种场景均不改变窗户。
手动、自动及单设备命令清除场景标记。自动模式按既有传感器阈值逻辑运行。

## ESP32 应用

目录 `F:\esp\v6.0.2\esp-idf-2\xiaozhi-stm32`，SDK 使用上级 ESP-IDF 6.0.2。
本地小智源码来源 `F:\esp32\xiaozhi-esp32-main\xiaozhi-esp32-main`。
板型 `bread-compact-stm32-lcd` 继承本地工程的 ESP32-S3、ST7789 240x320 和音频引脚，使用独立固件身份。
该板型以 STM32 工具替换示例灯，GPIO18 只用于串口 RX。实物 ESP32 屏幕、音频和 Flash/PSRAM 配置仍需烧录前核对。

- `self.stm32.set_device(device, on)`：device 为 light/fan/window/door，on 为布尔值。
- `self.stm32.set_mode(mode)`：mode 为 manual/auto/sleep/away。
- 串口请求队列容量 4，后台任务顺序发送；队满拒绝新请求，发送错误记日志。
- 返回入队状态，不冒充 STM32 已收到、已执行或门窗已到位。

设备端 MCP 通过小智现有设备连接上报工具；云端外部 MCP 接入点不是设备语音 WebSocket 地址。
不在源码、配置或文档中保存外部接入点 token。参考 [小智设备端 MCP 文档](https://github.com/78/xiaozhi-esp32/blob/main/docs/mcp-usage.md)。

## 实物验收

1. 核对两块板型号、接线、供电和固件版本；STM32 烧录含 USART3 接收入口的新固件。
2. 串口助手连接 STM32 PB11，以 9600 HEX 先发送 `F4 06 07 FB`，等待至少 350ms，再发送 `F4 06 01 FB` 验证开灯。
3. ESP32 烧录对应板型固件并绑定小智，依次验证灯、风扇、窗户、门八个动作。
4. 验证手动/自动切换、睡眠/离家动作和 OLED 模式显示；模式切换的其他设备副作用应符合上文。
5. 同时使用离线语音 USART1 和 ESP32 USART3，确认半包不混合，两路有效命令均可执行。
6. 验证配网提示期间控制、快速请求队满、断开 STM32 后仅提示入队而不声称到位。
