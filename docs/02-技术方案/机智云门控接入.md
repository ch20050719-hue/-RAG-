# 机智云门控与场景接入

## 当前状态

用户在自己的机智云开发者账号下新建产品“STM32智能家居”，产品包含 15 个数据点。当前核对的 MCU SDK 位于 `stm32/GizwitsMCUCommon20260930220056759c81f59e/MCU_Common_source`，三个可写枚举已正确生成。两个 SDK 目录、压缩包和带有旧凭据的只读固件基线被 Git 忽略。

`stm32/程序` 工作副本已接入 `Door_Target` 和 `Home_Scene` 的下行解析、事件处理及上行状态报告。三个枚举、字段顺序、标志位顺序、数据点宽度和数值比例已与新 SDK 静态核对一致；本地凭据与该包相同。门控上报表示 MG90S 最近接受的目标，不表示门体已到位。Keil `SmartHome_STM32F103C6` 历史全量编译通过；新增逻辑测试断言尚未执行，云端、APP、模组重配和实物联调待记录。代理未执行烧录或申请产品发布；当前板卡实际固件版本及产品发布状态未确认。

## 枚举定义与协议核对

| 数据点 | 枚举范围文本框内容（英文逗号分隔） | 序号 | 位宽 |
|---|---|---|---|
| `System_Mode` | `手动,自动` | 0、1 | 1 位 |
| `Door_Target` | `未下发,开门,关门` | 0、1、2 | 2 位 |
| `Home_Scene` | `正常,睡眠,离家` | 0、1、2 | 2 位 |

新包的系统模式具有 `VALUE0`、`VALUE1`，门控和场景均具有 `VALUE0`、`VALUE1`、`VALUE2`，与工作副本一致。旧包只有一个枚举值并带裸换行文字的问题已在新包中消除。官方[数据点编辑指南](https://dev.gizwits.com/zh-cn/document/m2m/i_021_editdp/)说明，文本框中的枚举值用英文逗号分隔；若界面使用逐项添加控件，则逐项添加。

所有布尔与枚举共占 9 位，全量上报位区需要 2 字节。工作副本的 `COUNT_BIT` 已同步为 2；数据点标志位占 2 字节，数值区占 10 字节，全量数据点载荷合计 14 字节。若沿用旧的 `COUNT_BIT=1`，周期全量上报所用缓冲区会少分配一字节。

核对的 55 项公开协议宏均与新包一致。事件枚举编号是 MCU 内部符号，不在报文中传输；工作副本沿用内部编号，不影响已核对的标志位和数值布局。静态核对和编译成功不能替代 APP 与板卡端到端验证。

## 门控制

- `Door_Target=0` 不触发舵机动作。
- `Door_Target=1` 调用既有 `MG90S_Open()`；`Door_Target=2` 调用既有 `MG90S_Close()`。
- 超出 0～2 的值会被拒绝。
- `userHandle()` 读取 `MG90S_GetCommandedTarget()` 上报按键、语音或 APP 最近下发的目标。无位置传感器时，该值不代表门体已到位或已锁定。

## 场景控制

手机端使用一个 `Home_Scene` 枚举选择框，而不是两个独立开关。固件复用 `HomeScene_Apply()`：睡眠场景开启风扇、关闭灯光并下发关门和关窗目标；离家场景关闭风扇和灯光并下发关门目标。场景入口会切换为手动控制。

选择“正常”只清除场景标记，不切换 `System_Mode`，也不会自动恢复进入场景前的灯和风扇状态。手动控制灯、风扇、窗户或门时，固件将场景标记恢复为“正常”。

## 凭据配置

源码不保存 Product Key 或 Product Secret。Keil 工作副本从本机生成、被 Git 忽略的 `stm32/程序/Gizwits/gizwits_credentials.h` 读取凭据。生成文件前，在 PowerShell 会话中设置从机智云控制台取得的值：

```powershell
$env:GIZWITS_PRODUCT_KEY = "从控制台复制的 Product Key"
$env:GIZWITS_PRODUCT_SECRET = "从控制台复制的 Product Secret"
.\stm32\程序\Gizwits\generate_credentials.ps1
```

脚本要求两个值均为 32 位字母或数字。测试使用独立的占位凭据头文件，不依赖真实产品密钥。

本次会话的终端输出曾包含旧固件凭据定义。若这些旧凭据仍有效，请在对应机智云产品中轮换；新产品固件使用当前产品 SDK 中的凭据。

## 构建与验证

- 工作副本 Keil 目标保持 `STM32F103C6`；机智云代码生成选择“其他平台”，不为迎合生成器更改芯片目标。
- 生成 SDK 用于核对物模型和协议字段；合并时保留现有 `gizwits_protocol.c` 的长度检查和错误返回，不整体覆盖文件。
- `stm32/程序/tests/test_gizwits_protocol.c` 保留既有数值与错误返回测试，新增两个枚举的下行解码、值 2 上行编码、状态变化和越界拒绝，以及全量 14 字节上报、跨字节场景编码与输出尾部哨兵断言；`test_gizwits_product.c` 覆盖事件到 MG90S 与场景入口的映射。
- 2026-10-03 Keil `SmartHome_STM32F103C6` 全量构建：0 错误、0 警告。Code 28024、RO 3228、RW 184、ZI 1600 字节；已通过 MSVC 执行 12 个 C 测试程序，覆盖率尚未测量。
- 烧录文件为 `stm32/程序/USER/Objects/STM32_CGMCU.hex`。保持当前板卡、接线和 Keil 芯片配置；生成 SDK 不作为另一套板卡工程直接烧录。

## 板卡与 APP 联调顺序

1. 将工作工程的 HEX 烧录到现有 STM32 板卡，记录固件版本与接线版本。
2. 让 Wi-Fi 模组与当前新产品建立连接，在开发者中心设备管理中核对设备是否归属“STM32智能家居”。APP 仍显示旧产品时，先检查产品归属与绑定，不据此认定新数据点未生效。
3. 在新产品控制页面检查门控目标和场景选择框。手动模式下验证灯、风扇和窗户开关，再验证开门／关门；“未下发”不触发动作。
4. 依次选择睡眠、离家、正常，核对动作与设备回报；“正常”只清除场景标记，不恢复原来的执行器状态。再验证按键或语音操作后 APP 回报同步。
5. 改变设备状态或传感器读数，在实物设备的云端实时调试中核对上报字段；6 秒是传感器变化上报的间隔限制，不是全量上报周期。定时全量上报已改为时间差达到 600000 ms，修复跨过整点漏触发；ACK 超时后的补报和配网优先级已增加回归测试。重连后重复核对，记录 APP 下发、UART 报文、云端回报和实物动作，区分命令目标与位置反馈。

当前固件修复、测试与烧录后复测见[固件可靠性优化与验证](固件可靠性优化_2026-10-03.md)。云端日志查看步骤及历史验收边界见[新产品与云端上报交接](../交接_机智云新产品与云端上报_2026-10-02.md)。
