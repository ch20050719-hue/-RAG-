# STM32 与机智云 APP 智能家居远程控制

本项目当前面向低压桌面智能家居模型，目标是通过机智云 APP 远程控制实际硬件。控制路径为：

```text
机智云 APP ⇄ 机智云云端 ⇄ ESP8266 Wi-Fi ⇄ STM32 ⇄ 模型执行器
```

项目不以网页家居控制台或模拟设备作为交付入口。当前交付控制链路不使用 RAG、知识问答或 Agent。仓库中保留的旧软件演示代码不等同于实物功能。

当前项目的主要功能是 STM32 固件及其硬件控制。Python/RAG、Agent 和网页控制台不属于当前项目功能或交付依赖；相关旧源码已移至 `F:\agrnt\financial_rag`、`F:\agrnt\home-llm` 和 `F:\agrnt\.tmp-rag-merge` 备份保留，不作为当前工作区代码维护。用户已授权后续实现一个范围受限的 DeepSeek 语音控制网关，具体状态见下文；该网关目前尚未实现。

## 唯一 Git 仓库与语音控制计划

- 本项目唯一 Git 根目录：`F:\论文方向\大模型+RAG知识库`。STM32 工作副本为 `stm32\程序`，只读固件基线为 `stm32\程序原版，不要i修改`；不创建嵌套 Git 仓库。
- 提交默认只保存在本地，不推送远程。提交时只暂存明确的源码、测试和项目记忆文件；个人资料、历史备份和 Keil 编译/界面产物不进入提交。
- 用户确认的后续目标：把语音识别文本送到服务端，由 DeepSeek 解析成受限指令，再经机智云控制灯、风扇和窗户；每条设备控制命令先切到手动模式，再发送设备数据点。
- API 密钥只保存在服务端配置；模型输出必须经过固定设备/动作白名单校验。STM32 继续使用现有驱动和数据点，不接收任意 GPIO、PWM 或模型生成的代码。
- 语音平台能否向服务端提供识别文本、机智云实际物模型中的数据点名称/写权限，仍待核实。服务端、语音接入和端到端控制尚未实现；门锁舵机不在本次语音控制范围内。

## 当前功能范围

- 控制对象：低压 LED、5V 风扇、28BYJ 窗户机构、舵机锁门装置。
- 当前固件已有传感器代码：DHT11 温度/湿度、ADC 烟雾读数；另有 ADC 光照读数，其是否进入最终 APP 物模型待确认。
- APP 通过固定数据点发送开关/动作命令，STM32 执行后回报状态。
- 烟雾是唯一需要保留的相关检测项；没有独立火焰检测、“有人”检测或水泵。
- 仅使用低压桌面模型，不连接 220V 市电或真实住宅门锁。

水泵、火焰和“有人”传感器的模拟功能、网页家居演示模块、RAG/Agent 控制入口、场景和其他非必要演示能力已退出当前项目范围。相关旧软件代码保存在上述备份目录中，不能将其描述为当前产品功能。

## 接手开发顺序

1. 在机智云控制台核对产品物模型、设备绑定、数据点名称/类型/读写属性与 STM32 SDK。
2. 在板卡上抓取 Gizwits UART 帧，核对 APP 的 LED、风扇、窗户命令与状态回报。
3. 为 MG90S 锁门装置补充受限的机智云控制数据点和状态回报。
4. 在各 OLED 页面验证每秒采样、失效显示和自动控制的传感器有效性处理。
5. 按交接文档的验收清单进行 APP、ESP8266、STM32 和实物模型端到端联调。

固件已修复 UART 发送循环、窗户事件标志和阈值事件映射。窗户动作由 TIM3 逐步执行，语音命令按有效串口帧进入 FIFO；主机逻辑测试和 Keil 工程编译通过，APP、语音串口和实物行程联调尚未完成。传感器失效时固件会保留最后一次成功读数，但当前机智云物模型没有数据有效位，APP 无法直接识别旧读数。

## 关键约束

- 机智云 APP 只发送物模型中定义的受限命令；角度或预设位置的范围必须先按实物连杆校准，不接受任意 GPIO、Topic 或不受限的电机脉冲。
- APP 显示的执行状态应来自设备回报。无门磁或位置反馈时，只能描述“命令/目标状态”，不能确认机械结构已到位。
- 烟雾 ADC 原始值必须标注 raw；未标定前不得换算成 ppm 或声称具备消防级检测能力。
- 不在文档、代码、日志中记录 Wi-Fi 密码、机智云密钥、产品密钥或用户凭证。
- 硬件联调只使用低压桌面模型；禁止连接 220V 市电和真实住宅门锁。
