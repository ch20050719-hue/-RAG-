# 智能家居改造过程文档

## 1. 改造结论

本次改造已将项目业务范围收敛为智能家居。RAG 检索、Agent 编排、多轮会话、流式输出、权限与审计等通用能力保留；设备查询、设备控制、安全规则、机智云/协议适配和版本三 STM32 原型形成独立模块。旧财税链路不再作为当前产品入口、配置、知识数据或文档内容维护。

## 2. 已完成内容

### 2.1 领域切换

- 家居知识种子覆盖设备说明、环境数据、舒适度、场景和安全规则；
- 意图分析、Graph 查询分类、工具路由和 Agent 能力配置均面向智能家居；
- Home Specialist 接入现有 Agent 编排和多轮会话流程；
- 前端品牌、导航、设置和设备页统一为智能家居表达。

### 2.2 设备与安全

- 增加设备模型、默认设备注册表和设备服务；
- 固定工具支持设备列表、单设备状态、环境读取、灯/风扇控制和预置场景；
- 控制请求经过注册、类型、在线、动作白名单、命令状态、TTL 和幂等校验；
- 控制结果包含 accepted、message、blocked_reason 和 ack 时间，避免把“已发送”误报为“已执行”。

### 2.3 MQTT 与硬件

- 提供模拟适配器和 MQTT 适配器，开发模式默认使用模拟适配器；
- MQTT 控制使用 QoS 1、结构化 JSON、request_id、过期时间和 ack 回执；
- 确认版本三硬件目标为 STM32F103C8T6 + ESP8266-01S，覆盖 DHT11、光敏电阻、MQ-2、OLED、低压灯/风扇、28BYJ 窗户和舵机锁门装置；
- 固件不接受任意 GPIO 指令，原型禁止接入 220V 市电。

## 3. 当前请求链路

```text
自然语言或前端 API
  → 会话上下文
  → Marvis 主 Agent/Coordinator
  → 知识/RAG、环境监测、设备控制子 Agent
  → 设备控制子 Agent 内部 ReAct 选择固定工具
  → 安全校验
  → 模拟或 MQTT 执行
  → 状态/ack 回执
  → 多轮会话结果
```

## 6. 后续联调步骤

1. 安装后端完整依赖，确认 FastAPI 应用可启动；
2. 使用 Mosquitto 或其他 MQTT Broker，记录地址、认证、TLS 和 ACL 配置；
3. 建立 STM32F103C8T6 固件并确认 ESP8266-01S 串口、机智云数据点、传感器引脚和执行器接线；
4. 先验证 availability/telemetry，再验证单设备控制和 ack；
5. 最后验证模式切换、阈值自动控制、断线、超时和重复 request_id 拦截。
