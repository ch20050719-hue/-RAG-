## 1. 目标

在没有 MQTT Broker 和 ESP32 硬件时，先验证智能家居设备控制的核心行为：设备注册、状态读取、固定动作、设备离线、命令过期和重复请求幂等。

模拟适配器与 MQTT 适配器保持相同的设备命令边界，便于后续替换通信实现，不让 Agent 直接接触 MQTT Topic 或 GPIO。

当前支持：

- 设备类型：`light`、`fan`；
- 传感器：温度、湿度、光照、人体；
- 固定动作：`set_state`；
- 状态：`on`、`off`；
- 场景：`sleep`、`away`、`movie`；
- REST：`/api/v1/home/devices`、`/api/v1/home/environment`、`/api/v1/home/scenarios`；
- Agent 工具：查询状态、读环境、开关灯/风扇、执行场景；
- MQTT Topic 契约与适配器（需 `paho-mqtt` 与 Broker）。

## 3. 数据与命令模型

### 3.1 设备注册

```python
DeviceRegistration(
    device_id="desk_light",
    room="study",
    device_type="light",
    online=True,
)
```

### 3.2 设备命令

```python
DeviceCommand(
    request_id="唯一 UUID",
    device_id="desk_light",
    action="set_state",
    state="on",
    expires_at="可选的过期时间",
)
```

### 3.3 执行回执

只有适配器完成状态更新后才返回成功回执。MQTT 适配器同样语义：消息发布成功不能直接视为设备执行成功，必须等待设备状态回执。

## 4. 安全边界

- 设备必须先注册才能控制；
- 设备离线时拒绝命令；
- 过期命令在状态变更前拒绝；
- 请求 ID 重复时返回第一次回执，不重复执行；
- 动作使用固定字面量，不接受任意服务名或底层指令；
- 安全规则层额外校验白名单与风险分级。
