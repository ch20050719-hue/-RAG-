# 小智室内环境查询

## 功能与边界

用户询问室内环境时，小智通过 `self.stm32.get_environment` 读取 STM32 的温度、湿度和相对光照数据，并据此组织语音回答。工具描述要求每次回答环境问题先读取数据；实际云端工具调用和回答内容须在设备上验收。

环境查询不下发控制命令、不切换手动/自动模式，不增加主动提醒或无人值守自动控制。温湿度可用于一般环境描述，不能把固件原有自动控制阈值当作舒适度标准。光照尚未实物标定，不能输出准确 lux 或按未经标定的阈值断言明暗；这三个指标不能判断空气质量或是否有人。

## 成熟方案调研

- 复用已有小智设备端 MCP 工具注册、现有设备连接及 STM32 传感器采样，不增加服务端或第三方依赖。[小智官方 MCP 文档](https://github.com/78/xiaozhi-esp32/blob/main/docs/mcp-usage_zh.md)
- ESP32 在独立任务中通过 UART 驱动接收，MCP 主线程只读缓存，避免等待串口影响对话。[Espressif UART 官方示例](https://github.com/espressif/esp-idf/blob/master/examples/peripherals/uart/uart_events/main/uart_events_example_main.c)
- STM32 复用标准库 TXE 中断发送，主循环不忙等。18 字节遥测帧是现有两端应用之间的新增约定，不改变机智云协议。[STM32F1 RM0008](https://www.st.com/resource/en/reference_manual/cd00171190.pdf)

## 数据路径

STM32 每秒执行已有 `Menu_UpdateSensors`，采样后将快照交给 USART3 的单帧发送缓冲。TXE 中断逐字节发送；若缓冲仍忙，跳过该次上报。接收控制指令的 RXNE 分支继续独立工作。

接线沿用 STM32 PB10 TX → ESP32 IO18 RX、ESP32 IO17 TX → STM32 PB11 RX，共地，9600 8N1。板型保持 `bread-compact-stm32-lcd`，屏幕保持 128×160，不修改只读原版和 ESP-IDF SDK。

ESP32 接收任务解析帧并在临界区更新缓存。查询工具在临界区复制缓存，离开临界区后序列化；回调不执行串口读写，不等待新采样。

## 遥测协议

固定 18 字节，整数小端：

| 字节索引 | 字段 |
|---|---|
| 0 | 帧头 `F4` |
| 1 | 遥测类型 `08`，原控制帧类型仍为 `06` |
| 2 | 协议版本 `01` |
| 3 | bit0 温湿度有效，bit1 光照有效；其余位为 0 |
| 4、5 | 温度 ℃、湿度 %RH，各 1 字节 |
| 6–7 | `4096 - ADC` 相对光照值 |
| 8–11 | STM32 温湿度采样年龄，毫秒 |
| 12–15 | STM32 光照采样年龄，毫秒 |
| 16 | 字节 1–15 的 XOR |
| 17 | 帧尾 `FB` |

有有效标志时，温度范围为 0–50℃，湿度 0–100%RH，光照 raw 1–4096。无效字段可以携带最后一次读数，但查询结果将其替换为 `null`。单个传感器失效不遮蔽另一传感器的正常数据。

解析器使用 18 字节滑窗，检验帧头、类型、版本、有效位、数值范围、校验及帧尾。载荷中的 `F4`、`FB` 不打断帧，损坏或截断后可从后续正确帧恢复。

## 数据有效性

温湿度复用 `DHT11_DataValid`；光照复用 `ADC_DataValid`。现有 ADC 有效位同时要求光敏和烟雾通道采集成功，暂不拆分这一保守判断。

有效性同时要求传感器有效标志和数据年龄不超过 3000ms。ESP32 将收到帧后经过的时间累加到 STM32 报告的采样年龄，避免断开后仍把旧数据当作实时值。加法溢出时饱和为最大年龄。

未收到帧时 `received=false`；收到过帧但过期时仍可 `received=true`，对应有效位为 false、读数为 null。`received` 不表示当前在线。失效读数不能当作 0℃、0%RH 或全黑。

返回字段包括 `temperature_c`、`humidity_percent_rh`、`light_raw`、`dht_valid`、`adc_valid`、两项 `age_ms`、`max_age_ms` 和 `light_unit=relative_raw_uncalibrated`。

## 构建与验证

STM32 工作工程：`stm32/程序/USER/STM32_CGMCU.uvprojx`，目标 `SmartHome_STM32F103C8`。小智应用：`F:\esp\v6.0.2\esp-idf-2\xiaozhi-stm32`。

环境查询的动态测试复用 USART 集成和小智控制测试入口，覆盖真实编码到真实解析的互通、噪声与分片、独立失效、年龄边界、时钟回绕、无数据、断开后过期、初始化失败清理以及查询回调不执行 UART IO。

本轮验证：STM32 USART 真实驱动模拟通过；小智 185 项控制协议与真实 STM32 解析器互通、77 项 UART/RX/MCP 回调、104 项环境解析与真实 STM32 编码互通、47 项超时和 18 项角色动画检查通过。STM32 DHT11、ADC、自动控制、阈值及 UI 刷新既有测试通过。Keil 全量构建 0 错误、0 警告，Code 28916、RO 3420、RW 188、ZI 1716 字节。

小智标准全量重新配置受依赖管理器联网核对阻塞；关闭新版本提示和缩短网络超时未解除，本地组件备用入口也缺少 manifest 组件名映射。最终复用此前成功的 128×160 Ninja 编译与链接参数，重新编译 `stm32_uart_device.cc` 和引用环境工具的板型源文件，再归档、完整链接、生成镜像及合并。参数由 `ninja -t commands`、`ninja -t compdb -x` 导出，未修改 SDK 或依赖源码。恢复了标准入口移除的原 `sdkconfig`，其 SHA256 与构建前备份相同。本轮不记为标准入口全量重新配置通过。

## 实物验收

1. 两块板均烧录同次交付固件，记录文件哈希；保留已确认接线和低压供电。ESP32 当前记录端口为 COM10，实际端口变化时以最新核实结果为准。
2. 小智联网后询问“现在室内温度和湿度是多少”，核对工具注册和调用日志，并与 STM32 OLED 数值比较，允许采样时刻造成的小幅差异。
3. 遮挡、照亮光敏模块，检查 `light_raw` 是否随实际明暗变化；记录范围后再决定明暗阈值，目前不宣称已标定。
4. 安全断开温湿度传感器，确认温湿度不可用时仍能获取正常光照；复原后检查数据恢复。
5. 断开 STM32 → ESP32 的 TX 数据线，等待超过 3 秒再询问，确认不再报告旧实时读数；恢复后约一个采样周期内应重新收到数据。
6. 查询期间验证灯、风扇、窗户、门、四种模式及离线语音；查询本身不应触发动作。验证角色动画、回复尾音及 8 秒空闲待机。

未经成功烧录日志、真实工具调用日志和传感器对照结果，不将功能记为实物通过。
