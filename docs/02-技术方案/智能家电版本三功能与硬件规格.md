# 智能家电系列版本三：功能与硬件规格

> 文档性质：当前硬件功能规格。后续软件、Agent、MQTT 和 STM32 固件实现以本文档为准。
>
> 最后更新：2026-09-19

## 1. 产品定位

本系统是基于 STM32F103C8T6 的智能家电控制与居家环境监测原型，具备本地传感、OLED 显示、语音控制、按键/手机手动控制、阈值自动控制、蜂鸣器报警和机智云远程控制能力。

系统控制对象为：

- 风扇；
- 灯光；
- 窗户（28BYJ 步进电机模拟开关窗）；
- 舵机锁门装置（独立门锁执行器）。

## 2. 功能规格

### 2.1 检测功能

| 数据 | 器件 | 接入方式 | 用途 |
|---|---|---|---|
| 温度 | DHT11 | 数字接口 | 温度显示、自动风扇控制 |
| 湿度 | DHT11 | 数字接口 | 湿度显示、自动通风控制 |
| 光照强度 | 光敏电阻模块 | ADC | 光照显示、自动补光 |
| 烟雾浓度 | MQ-2 | ADC | 烟雾显示、自动通风和报警 |

MQ-2 需要预热和量程/阈值校准。系统应把它作为“实验烟雾浓度/模拟量”使用，不在文档中宣称为经过消防认证的烟雾报警器。

### 2.2 显示功能

OLED 至少显示：

- 温度；
- 湿度；
- 光照强度；
- 烟雾浓度或 ADC 映射值；
- 风扇状态；
- 灯光状态；
- 窗户状态；
- 当前模式：手动/自动；
- 报警状态；
- 网络或机智云连接状态。

### 2.3 语音功能

SNR9902 负责本地语音识别或语音指令触发，通过 STM32 可识别的串口/数字协议传递结果。语音模块本身不执行 RAG、LLM 或设备安全校验。

支持的本地语音意图至少包括：

- 打开/关闭风扇；
- 打开/关闭灯光；
- 打开/关闭窗户；
- 切换手动模式；
- 切换自动模式。

云端自然语言控制仍走电脑端的 LLM + RAG + Marvis 风格主 Agent/子 Agent 链路；SNR9902 是独立的本地控制入口，不能把本地语音模块描述成云端 LLM。

### 2.4 手动模式

手动模式支持：

- 手机机智云 APP 控制；
- STM32 板载按键控制；
- 本地语音模块控制。

手动模式下，用户可以控制风扇、灯光和窗户。自动阈值规则不应在手动模式下强制改写用户操作，但报警策略需要明确：建议保留烟雾报警，是否自动执行风扇/开窗由最终模式规则确定。

### 2.5 自动模式

| 条件 | 动作 | 报警 |
|---|---|---|
| 温度高于温度阈值 | 开启风扇 | 蜂鸣器报警 |
| 湿度高于湿度阈值 | 开启窗户、开启风扇 | 蜂鸣器报警 |
| 烟雾高于烟雾阈值 | 开启风扇进行通风 | 蜂鸣器报警 |
| 光照低于光照阈值 | 开启灯光补光 | 默认不报警 |

自动动作必须经过 STM32 本地状态机执行。后端 Agent 不直接改写自动模式下的底层 GPIO 或阈值。

软件模拟阶段用同一规则验证行为：`manual` 仍记录报警但不自动覆盖灯、风扇和窗户；`automatic` 在连续样本确认后调用固定设备服务执行联动。`normal`、`sleep`、`away` 继续作为云端场景配置存在，与手动/自动模式相互独立。

### 2.6 报警功能

自动模式下，任一传感器超过阈值时，蜂鸣器报警，并在 OLED 和手机端显示报警来源。

报警记录至少包含：

- 报警类型；
- 当前值；
- 阈值；
- 发生时间；
- 当前模式；
- 已执行动作；
- 是否恢复正常。

阈值比较应考虑连续采样确认和恢复滞回，避免传感器瞬时抖动导致执行器频繁启停。

### 2.7 阈值调节

以下阈值可通过按键和手机 APP 调节：

- 温度上限；
- 湿度上限；
- 光照下限；
- 烟雾上限。

阈值必须经过范围校验并持久化保存。云端 Agent 可以通过固定的 `set_threshold` 工具提交合法阈值，但不能直接发送任意寄存器或 GPIO 指令。

## 3. 控制架构

### 3.1 本地硬件控制链路

```text
传感器 / 按键 / SNR9902
          ↓
STM32F103C8T6 本地状态机
          ↓
OLED / 蜂鸣器 / 风扇 / 灯光 / 28BYJ 窗户 / 舵机锁门装置
```

### 3.2 云端智能控制链路

```text
用户自然语言
    ↓
Marvis 风格主 Agent
    ├── 知识/RAG 子 Agent
    ├── 环境监测子 Agent
    └── 设备控制子 Agent（内部 ReAct）
            ↓
        固定设备工具
            ↓
        DeviceService / 协议适配器
            ↓
        机智云适配器或受控 MQTT 桥
            ↓
        ESP8266-01S
            ↓ UART/协议
        STM32F103C8T6
```

机智云链路不能直接等同于当前项目的自定义 MQTT Topic。需要单独实现或确认 `GizwitsAdapter`/协议桥，把云平台数据映射为内部统一的设备状态和命令模型。

## 4. 主要元器件

| 序号 | 元器件 | 系统职责 | 必须确认事项 |
|---:|---|---|---|
| 1 | STM32F103C8T6 | 主控、采集、状态机和执行控制 | 时钟、GPIO、ADC、定时器、串口资源 |
| 2 | OLED | 本地数据显示 | I2C/SPI 接口和地址 |
| 3 | 光敏电阻传感器 | 光照 ADC 采集 | 分压、电压范围、阈值标定 |
| 4 | DHT11 | 温湿度采集 | 时序和采样周期 |
| 5 | MQ-2 | 烟雾模拟量采集 | 预热、ADC 分压、阈值标定 |
| 6 | 28BYJ-48 + 驱动模块 | 窗户步进电机模拟 | 驱动型号、步数、开关限位 |
| 7 | ESP8266-01S | Wi-Fi/云平台通信 | AT 固件或自定义固件、串口波特率 |
| 8 | USB 灯/USB 风扇 | 低压执行器 | 必须使用 MOSFET/继电器和独立 5V 供电 |
| 9 | 有源蜂鸣器 | 报警输出 | GPIO 电平和驱动电流 |
| 10 | SNR9902 | 本地语音入口 | 指令表、串口协议和供电 |
| 11 | 舵机锁门装置 | 门锁执行器 | PWM 频率、角度、锁止状态反馈 |

## 5. 安全和边界

- STM32 只接收固定动作和合法阈值，不接收任意 GPIO、寄存器或 MQTT Topic。
- USB 灯、USB 风扇和舵机使用低压独立供电，不接入 220V 市电。
- 28BYJ 步进电机必须经过专用驱动模块，不能直接由 STM32 GPIO 带动。
- MQ-2 数值只用于实验演示，不表述为消防级浓度测量。
- 云端 Agent 的执行结果必须以 STM32/云平台回执为准，不能把“命令已发送”当成“设备已执行”。
- 这里的回执是通信/执行结果，不等于额外增加一套“开门/关门前必须由服务端确认”的交互状态。
- 普通开门、关门不设置独立服务端确认状态，但仍执行设备在线、动作白名单、TTL、幂等和回执校验。

## 6. 待硬件联调确认

1. STM32F103C8T6 的具体开发板版本和引脚图；
2. OLED 使用 I2C 还是 SPI；
3. MQ-2 模块输出是否需要分压后接 STM32 ADC；
4. 28BYJ 驱动模块型号及窗户开、关限位方案；
5. ESP8266-01S 使用 AT 固件还是独立云平台固件；
6. 机智云产品数据点和命令协议；
7. SNR9902 的串口命令编码；
8. 舵机锁门装置的 PWM 参数和锁状态反馈；
9. 手动模式下烟雾报警是否仍强制开启风扇；
10. 自动模式动作的连续确认次数、恢复阈值和滞回范围。
