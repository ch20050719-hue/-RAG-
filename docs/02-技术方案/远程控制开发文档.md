# 智能家居远程控制开发文档

## 1. 目标链路

```text
手机 APP / Vue 控制台
        ↓ HTTPS
FastAPI Home API / 主 Agent
        ↓ 固定工具与 DeviceService
模拟适配器或受控 MQTT/Gizwits Adapter
        ↓
ESP8266 Wi-Fi → STM32F103C8T6
        ↓
温湿度/烟雾/火焰/有人、OLED、LED、风扇、水泵、蜂鸣器、舵机门锁
```

前端和 Agent 不直连 Broker、STM32、GPIO 或机智云数据点。后端必须等待设备 ack，不能把网络发布成功当成执行成功。

## 2. 当前软件复用能力

- Vue 控制台和 `src/api/home.ts`；
- FastAPI `/api/v1/home` 设备、环境、阈值、模式和门锁 API；
- RAG、主 Agent、环境监测和设备控制子 Agent；
- `device_tools.py` 固定工具和 `DeviceService` 安全校验；
- `SimulatedDeviceAdapter`、`MqttDeviceAdapter`、TTL 和 `request_id` 幂等；
- 环境报警、自动联动和前端轮询展示。

尚未完成的是 STM32 固件、OLED/按键驱动、密码键盘、IC 卡、ESP8266 UART/固件和机智云产品数据点配置。

## 3. 远程功能

APP 可查看温度、湿度、烟雾、火焰和有人状态，查询报警和设备在线状态；可切换手动/自动模式、调整三类阈值，并控制 LED、风扇、喷淋水泵、蜂鸣器和门锁。

远程开锁必须提供有效的 APP 认证结果，和密码、IC 卡一样进入门锁专用服务。普通设备状态接口不能控制门锁、水泵或蜂鸣器。

## 4. 云端与协议边界

机智云数据点由适配器映射为内部固定模型：

| 内部对象 | 示例数据 |
|---|---|
| telemetry | `temperature`、`humidity`、`smoke`、`flame`、`presence` |
| actuator state | `light`、`fan`、`water_pump`、`buzzer` |
| door lock | `unlock`、`lock`、`open_door`、`close_door` |
| mode | `manual`、`automatic` |
| thresholds | `temperature_max`、`humidity_max`、`smoke_max` |

适配器必须保留 `request_id`、过期时间、在线状态和 ack；不得把任意数据点名称透传到模型。

## 5. 实施顺序

1. 用 `HOME_DEVICE_ADAPTER=simulated` 完成 API、Agent、前端和自动联动回归；
2. 确认 STM32 引脚、UART、电源、OLED、按键、传感器和执行器驱动；
3. 实现本地手动/自动状态机和密码/IC 卡认证；
4. 配置 ESP8266 与机智云，建立 telemetry、availability、command/ack 映射；
5. 在隔离 Broker 中联调，再进行 APP 远程查看和控制验收；
6. 记录 Broker、固件、数据点、板卡、接线和测试结果。

## 6. 安全和部署

- 远程访问使用 HTTPS、认证、租户隔离和最小权限；
- MQTT 使用账号、ACL、TLS 和唯一 Client ID；
- 不做 STM32/ESP8266 公网端口映射；
- 不在日志、提示词、前端或文档中记录密钥、密码、私钥、任意 Topic 或 GPIO；
- 版本三只允许低压桌面原型，禁止 220V 市电和真实住宅门锁。

外部参考项目只用于比较架构模式，不作为当前硬件事实源。当前事实以版本三规格、当前架构决策和 MQTT 联调说明为准。
