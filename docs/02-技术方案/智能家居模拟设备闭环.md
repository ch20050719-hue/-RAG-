# 智能家居模拟设备闭环

## 1. 目标

在没有 STM32、ESP8266-01S 和机智云环境时，先验证版本三软件闭环：传感器注册与读取、LED/风扇/喷淋水泵/蜂鸣器控制、手动/自动模式、阈值联动、门锁安全校验、命令过期和重复请求幂等。

模拟适配器与 MQTT 适配器共享同一套 `DeviceService` 和回执模型。Agent、前端和测试只能经过固定工具/API，不直接接触 GPIO、任意 Topic 或机智云数据点。

## 3. 自动联动

自动模式下，每次环境评估只执行下列固定规则：

| 条件 | 联动 |
|---|---|
| 温度超过 `temperature_max` | 风扇开启、蜂鸣器报警 |
| 烟雾超过 `smoke_max` | 风扇开启、蜂鸣器报警 |
| 火焰状态为 1 | 喷淋水泵开启、蜂鸣器报警 |
| 有人状态为 1 | LED 开启 |
| 湿度超过 `humidity_max` | 生成环境报警；当前不自动启动执行器 |

手动模式只执行按键或 APP 的明确命令，不因环境读数自动改变执行器状态。场景预设独立于手动/自动模式：正常不改变设备，睡眠关闭 LED 并尝试反锁，离家关闭 LED/风扇并尝试锁门。

场景预设对人工工具采用后端白名单：正常允许 LED、风扇、水泵、蜂鸣器、阈值、手动/自动模式和门锁；睡眠允许 LED、风扇、蜂鸣器和门锁；离家允许水泵、蜂鸣器和门锁。环境查询、设备状态查询、场景切换和自动安全联动在三个场景中始终保留。白名单拒绝会返回带场景名的 `blocked_reason`，不依赖前端按钮隐藏。

## 4. 命令与安全边界

- 设备必须已注册、类型匹配、在线且命令未过期；
- `request_id` 在设备服务边界与规范化命令指纹绑定。相同 ID、相同命令重放第一次回执；相同 ID 携带不同设备或动作/状态时拒绝，包括普通设备与门锁控制域之间的冲突；MQTT 命令仍在等待 ack 时，同 ID 重试不会再次发布；暂时性超时不缓存为最终失败，允许同指纹重试，设备端仍须自行去重；
- 水泵、蜂鸣器和门锁不能通过通用开关接口控制，必须经过各自固定入口；
- 模拟适配器允许模拟锁舌/反锁状态；MQTT 当前仅实现门体开/关动作，硬件锁舌/反锁动作尚无固件协议，故 MQTT 模式下拒绝这些动作，不返回虚假的成功状态；
- Agent 门锁工具不接受模型提供的授权/二次确认布尔参数，授权动作必须通过登录保护的设备控制 API；
- MQTT 普通设备 ack 必须显式提供并匹配请求 ID、房间、设备、动作和目标状态；门体动作 ack 必须显式提供 `ack_status`，且只有 `accepted=true`、`ack_status=success` 才算控制器确认完成；错误或迟到 ack 不更新设备状态；控制器没有位置传感器时，这仍不是实测门体位置；
- 失败只返回可解释原因，不泄露底层 Topic、GPIO 或云平台密钥。

当前缓存位于适配器/服务进程内，仅覆盖同一运行实例。进程重启后记录会丢失，门锁逻辑状态也不从硬件恢复，不能当作实物门磁/锁舌的权威状态；接入真实门锁前需实现状态同步或 fail-closed 的未知状态策略。真实协议桥和 STM32 仍需独立按 `request_id` 与命令指纹去重，并在重启策略中明确缓存保留时间。因此，该闭环验证的是应用层重试控制与回执关联，不代表跨进程或断电后的 exactly-once 执行保证。
