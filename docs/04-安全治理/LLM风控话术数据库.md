# 智能家居交互安全规则

本文档只服务智能家居对话和设备控制。规则用于输入预检、工具调用前校验、设备回执核对和安全回复，不把攻击样本或设备凭据写入普通知识库。

## 1. 控制规则

| 规则 | 触发条件 | 默认动作 | 用户提示方向 |
|---|---|---|---|
| 设备未注册 | device_id 不在注册表 | BLOCK | 请先绑定或选择已注册设备 |
| 类型不匹配 | 灯工具操作风扇或反之 | BLOCK | 当前设备不支持该操作 |
| 设备离线 | online=false | BLOCK | 设备当前离线，请恢复连接 |
| 动作不允许 | 非 `on/off` 或非预置场景 | BLOCK | 仅支持当前设备能力范围 |
| 命令过期 | `expires_at` 已过期 | BLOCK | 控制请求已失效，请重新发起 |
| 重复请求 | request_id 已处理 | RETURN_FIRST_RESULT | 已返回原请求结果 |
| ack 不匹配 | 设备或 request_id 不一致 | IGNORE_AND_AUDIT | 设备回执未通过校验 |
| ack 超时/失败 | 未收到 ack 或 ack 表示失败 | FAIL | 设备未确认执行，不报告成功 |

## 2. 对话规则

- 不确定设备身份、房间或目标动作时先澄清，不猜测设备；
- 不承诺未收到 ack 的控制已经执行；
- 不生成任意 MQTT Topic、GPIO、脚本或底层凭据；
- 对电源、燃气、门锁、加热等未注册高风险设备直接拒绝；
- 知识库无依据时明确说明，并优先给出设备说明或当前状态依据；
- 错误回复只展示用户可理解的原因，不展示堆栈、密码或内部连接信息。

## 3. 规则处理顺序

```text
规范化输入
  → 身份/租户权限
  → 设备注册与能力
  → 在线、动作、参数和 TTL
  → request_id 幂等
  → MQTT ack/设备状态核对
  → 安全回复与审计
```

## 4. 审计字段

每条控制尝试至少记录：`interaction_id`、`request_id`、用户/租户标识、设备 ID、动作、校验结果、阻断原因、适配器、ack 状态和时间戳。敏感凭据不进入日志。

## 5. 测试要求

必须覆盖未注册、类型不符、离线、非法状态、过期、重复 request_id、ack 超时、否定 ack 和跨租户访问。规则实现位于 `rag_backend/app/home_automation/safety_rules.py`，工具入口位于 `device_tools.py`。
