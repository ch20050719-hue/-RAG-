## 1 项目目标

项目面向单房间低压实验原型，完成环境检测、OLED 显示、手动控制、自动联动、阈值调节、门锁控制、机智云接入和 APP 远程控制。

大模型只负责理解自然语言、匹配系统已经配置的能力、调用固定设备工具和解释执行结果。手动/自动模式、阈值、报警条件和联动动作均由系统预先设定，不由模型临时生成。

本项目面向单房间智能家居实验场景，研究大模型如何将自然语言转换为受控的设备操作意图，并通过固定设备工具、设备状态验证、安全规则和执行回执完成环境感知与安全控制。自动联动由预设规则和本地状态逻辑执行，大模型不直接访问底层硬件，也不生成新的控制规则。

## 2 当前功能范围

| 功能类别 | 当前确认内容 |
|---|---|
| 检测 | 温度、湿度、烟雾浓度、火焰、是否有人 |
| 显示 | OLED 显示传感器数据、设备状态和报警状态 |
| 手动模式 | 按键或 APP 控制风扇、LED、舵机开关门和喷淋水泵 |
| 自动模式 | 温度超上限开风扇并报警；烟雾超上限开风扇通风并报警；检测到火焰启动喷淋并报警；检测到有人开启 LED |
| 阈值调节 | 通过按键或 APP 设置传感器阈值，并进行范围校验 |
| 开锁方式 | 密码、IC 卡、APP |
| 云平台 | ESP8266 WiFi 模块连接网络并接入机智云 |
| 远程控制 | APP 查看传感器数据、报警状态和设备状态，并远程控制设备 |

喷淋水泵只作为低压实验和动作模拟装置，不接入高压水路。系统禁止接入 220V 市电和真实住宅门锁。

## 3 当前系统结构

```text
按键 / APP / 自然语言
          ↓
预设模式与安全规则
          ↓
主 Agent：理解请求、匹配能力、调度固定工具
          ↓
设备服务与安全校验
          ↓
模拟适配器或 ESP8266 / 机智云适配器
          ↓
STM32F103C8T6
          ↓
OLED / 蜂鸣器 / LED / 风扇 / 舵机 / 喷淋水泵
          ↓
设备状态与执行回执
```

自动模式的安全联动优先由 STM32 本地状态机执行，避免网络或大模型响应延迟影响风扇、蜂鸣器和喷淋动作。

## 9 不能违反的约束

- 所有设备控制必须经过 `device_tools.py`、`DeviceService` 和安全规则。
- 模型、前端和 STM32 不得接受任意 GPIO、任意 MQTT Topic 或任意底层命令。
- 本地开发默认使用 `HOME_DEVICE_ADAPTER=simulated`，真实联调时才显式切换到 MQTT 或机智云适配器。
- 控制成功必须以设备状态或 ack 为依据，不能把“命令已发送”当成“设备已执行”。
- 控制命令必须校验设备注册、设备类型、在线状态、参数、TTL、`request_id` 和回执关联。
- 自动模式规则必须是预先配置的固定规则；模型不能临时创建新的自动控制逻辑。
- 硬件只允许低压 LED、低压风扇、舵机和实验喷淋水泵，禁止接入 220V 市电。
- 烟雾和火焰检测只用于实验原型，不作消防安全认证承诺。

## 10 容易重复出现的问题及避免方式

| 问题 | 避免方式 |
|---|---|
| 使用旧 ESP32、光照或窗户方案推断当前硬件 | 以本文件和最新功能报告为准，硬件参数以现场资料为准 |
| 把多个模式和临时规则混在一起 | 当前只保留手动模式、自动模式和预设阈值/联动规则 |
| 把发布命令误判成执行成功 | 必须等待匹配的设备状态或 ack |
| 直接让模型生成底层控制命令 | 只允许调用固定工具，服务层做最终校验 |
| 只改 Word 报告而不更新代码和技术文档 | 完成功能实现后同步更新模型、工具、API、前端和技术方案 |

## 11 验证和交接标准

交接完成前至少确认：

- 后端家居单元测试通过；
- 温湿度、烟雾、火焰和有人状态均能在模拟设备中读取；
- 手动模式能控制风扇、LED、舵机和喷淋水泵；
- 自动模式能按预设规则完成风扇、蜂鸣器、喷淋和 LED 联动；
- 阈值可以通过按键或 APP 调节并经过范围校验；
- 密码、IC 卡和 APP 开锁均有明确成功/失败结果；
- APP 能查看数据和远程控制，机智云联调记录包含 Broker/平台、固件、数据点和接线版本；
- `git diff --check` 通过，前端 `npm run build` 通过；
- 真实硬件尚未联调的内容明确标记为待验证。
