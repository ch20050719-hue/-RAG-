# STM32 串口语音控制

## 应用与硬件

应用目录：`F:\esp\v6.0.2\esp-idf-2\xiaozhi-stm32`。
开发框架：上级 `esp-idf-2`（ESP-IDF 6.0.2）。
本地来源：`F:\esp32\xiaozhi-esp32-main\xiaozhi-esp32-main`。
STM32 协议依据：`F:\论文方向\大模型+RAG知识库\stm32\程序`。用户已确认实际芯片 STM32F103C8T6，控制接口 USART3。

独立板型 `bread-compact-stm32-lcd` 使用 ESP32-S3，按用户确认配置 ST7735 128×160，保留既有显示和音频引脚。
烧录前核对板卡和固件版本；不以历史 240×320 构建替代当前屏幕规格。
新板型使用真实 STM32 工具，GPIO18 用作 UART RX。

| ESP32 | STM32 |
|---|---|
| IO17 TX | PB11 / USART3_RX |
| IO18 RX | PB10 / USART3_TX |
| GND | GND |

串口 9600、8N1，3.3V 逻辑。STM32 需要烧录带 USART3 接收入口的新固件。
PA9/PA10 保留离线语音串口；PA2/PA3 保留机智云串口。USART1、USART3 使用独立帧解析状态。
STM32 工程按用户确认的 C8 配置，64 KB Flash、20 KB RAM，目标名 SmartHome_STM32F103C8。
仅使用现有低压模型，不改变执行器驱动或供电。

## MCP 工具

`self.stm32.set_device`：参数 `device` 为 `light`、`fan`、`window`、`door`；`on` 为布尔值。
每次先切手动模式，等待 350ms，再发送设备命令。
从自动切手动时，STM32 先关闭灯、风扇和窗户并停止蜂鸣器，这是现有 STM32 固件的行为。

`self.stm32.set_mode`：参数 `mode` 为 `manual`、`auto`、`sleep`、`away`。
模式工具只发送对应模式命令；自动模式不会被额外的手动命令覆盖。

| 功能 | 命令字节 |
|---|---|
| 开灯 / 关灯 | 01 / 02 |
| 开风扇 / 关风扇 | 03 / 04 |
| 开窗 / 关窗 | 05 / 06 |
| 手动 / 自动 | 07 / 08 |
| 开门 / 关门 | 09 / 0A |
| 睡眠 / 离家 | 0B / 0C |

帧格式：`F4 06 命令 FB`。
睡眠：手动、风扇开、灯关、门关，不改变窗户。
离家：手动、风扇关、灯关、门关，不改变窗户。
手动/自动及单设备控制会退出睡眠/离家场景。

## 发送与结果

MCP 主循环只进行非阻塞入队，容量 4 个请求。一个后台任务顺序发帧，避免音频任务等待串口。
队列满会返回错误，不覆盖已有请求；发送错误写入 `STM32_UART` 日志，不自动重试。
STM32 的配网提示会短暂暂停模式切换收尾，350ms 间隔给它留出处理时间，但不构成执行确认。
模式请求之间至少间隔 100ms，避免高速灌入 STM32 的有限命令 FIFO。

返回“指令已加入串口发送队列”，并不证明 STM32 收到或机械到位。
现有控制串口没有 ACK 或执行器位置回传，不提供虚假的执行状态查询。温湿度和光照已有独立的只读环境遥测；有效性及过期处理见仓库根目录的室内环境查询说明。
应用重启会丢失尚未发送的队列；网络重连后的重复请求也没有跨重启去重保证。

设备端 MCP 复用小智设备的语音连接。用户提供的云端外部 MCP 接入点无需填入此固件，不将 token 写入源码、日志或文档。参考 [小智设备端 MCP 接入](https://github.com/78/xiaozhi-esp32/blob/main/docs/mcp-usage.md)。

## 编译与测试

在本应用目录运行 `scripts/build_stm32.ps1 -SdkRoot 'F:\esp\v6.0.2\esp-idf-2'`，它使用指定的 ESP-IDF 6.0.2 SDK 和本机已有的 Espressif 工具；可通过 `IDF_PATH` 指定 SDK，其他本机工具路径需与实际安装一致。

若复用本机已安装的依赖，可运行 `scripts/build_stm32.ps1 -UseLocalComponents`，首次将本地小智已有的 `managed_components` 原样复制到本应用，再交由组件管理器校验和维护。源工程依赖不作修改。
现有构建工具测试：`python -m unittest discover -s scripts/tests -v`。

## 实物验收

1. 核对 STM32 板上固件含 USART3 接收入口，在 PB11 用串口助手以 9600 HEX 先发送 `F4 06 07 FB`，等待至少 350ms，再发送 `F4 06 01 FB` 验证开灯。
2. 烧录新 ESP32 固件，确认启动日志为 TX17/RX18、9600 8N1。
3. 说“开灯、关灯、开风扇、关风扇、开窗、关窗、开门、关门”，核对实际动作和串口日志。
4. 说“切换自动模式”和“切换手动模式”，核对 OLED 和自动阈值控制。
5. 说“睡眠模式”“离家模式”，核对上述精确动作，尤其不要把离家当作关窗。
6. 覆盖自动转设备控制、睡眠转自动、离家转手动、重复命令以及配网提示期间控制。
7. 快速连续请求应在队列满时提示失败；断开 STM32 后不能返回已到位或已确认执行。

## 2026-10-11 无人说话自动待机

自动/实时聆听中，播放结束且连续 8 秒无语音活动时关闭音频会话，进入唤醒词待机。手动录音不受此限制。检测到语音或非空 STT 后等待回复，回复和尾音播放期间不运行空闲计时；60 秒无服务端回复会结束会话，持续语音会刷新等待上限。噪声被识别为语音可能延后待机，本功能不能保证消除误唤醒。

参数位于 `main/conversation_timeout.h`：`kSilenceUs` 为 8 秒，`kResponseWaitUs` 为 60 秒。`application.cc` 复用 VAD、主事件循环和播放排空检查；仅在支持 VAD 且启用音频处理器时应用，当前 S3 配置满足。实时播放期间继续记录 VAD 边沿，再次唤醒时重置计时并保留连续收音状态。

运行 `tests/run-conversation-timeout-tests.ps1`：47 项主机检查通过。运行原串口测试：协议/STM32 解析器 185 项、UART 63 项通过。构建工具 71 项中仍有 5 项既有 Windows 临时目录清理错误；未测覆盖率。
