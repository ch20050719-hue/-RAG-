# 智能家居改造实施方案

> 目标：在保留 RAG 检索、Agent 调度和多轮会话能力的前提下，将应用领域切换为智能家居，并落地设备工具、安全规则、MQTT 通信与 ESP32 桌面原型。

## 1. 改造原则

1. **架构与接口稳定**：保留现有 `/api/v1/chat`、`/api/v1/knowledge`、`/api/v1/multi-agent` 的通用接口语义；业务领域统一切换为智能家居，设备能力通过新模块、新路由和固定工具接入。
2. **后端是控制唯一入口**：前端与 Agent 不直接接触 MQTT Topic、GPIO；统一走固定设备工具。
3. **模拟与真实同契约**：`SimulatedDeviceAdapter` 与 `MqttDeviceAdapter` 共用同一套命令/回执模型。
4. **安全优先**：注册设备、动作白名单、参数范围、离线/过期/幂等拦截，全部在工具与适配器内部完成。

## 2. 目标架构

```text
Vue / App
   │ HTTP / SSE（原链路不变）
   ▼
FastAPI
   ├── 原：RAG / 会话 / 多 Agent（保留）
   └── 新：/api/v1/home/*
         │
         ▼
   home_automation 服务层
   ├── DeviceService（状态/控制/场景）
   ├── SafetyRules（白名单/范围/审计）
   ├── DeviceTools（Agent 固定工具）
   └── DeviceAdapter
         ├── SimulatedDeviceAdapter（无硬件联调）
         └── MqttDeviceAdapter（Broker + ESP32）
```

## 3. 模块落地清单

| 模块 | 路径 | 说明 |
|---|---|---|
| 设备与传感器模型 | `app/home_automation/device_models.py` | 灯/风扇控制 + 温湿度/光照/人体传感 |
| 安全规则 | `app/home_automation/safety_rules.py` | 白名单、参数、风险分级、拦截原因 |
| 设备服务 | `app/home_automation/device_service.py` | 注册、状态、控制、场景（睡眠） |
| Agent 工具 | `app/home_automation/device_tools.py` | LangChain 固定工具 |
| MQTT 适配 | `app/home_automation/mqtt_adapter.py` | Topic 契约、命令/回执 |
| 默认设备 | `app/home_automation/default_devices.py` | 桌面原型默认注册表 |
| API | `app/api/v1/endpoints/home_devices.py` | 设备查询与控制 REST |
| 能力配置 | `config/agent_home_capabilities.yaml` | 管家/环境/设备控制/舒适度 |
| ESP32 固件 | `esp32/esp32_home_node/` | 传感器上报 + LED/风扇执行 |
| 单元测试 | `tests/unit/test_home_automation_*.py` | 安全、服务、工具、MQTT 契约 |

## 4. MQTT Topic 契约（v1）

```text
home/v1/{room}/{device_id}/state/set     下发控制（后端 → 设备）
home/v1/{room}/{device_id}/state/ack     执行回执（设备 → 后端）
home/v1/{room}/{device_id}/telemetry     传感器上报（设备 → 后端）
home/v1/{room}/{device_id}/availability  online/offline
```

控制消息示例：

```json
{
  "request_id": "uuid",
  "action": "set_state",
  "state": "on",
  "expires_at": "ISO8601"
}
```

## 5. 领域切换策略

1. **Agent 能力**：使用 `agent_home_capabilities.yaml`，提供总管家、环境感知、设备控制、舒适度四类角色；默认能力、提示词和路由只面向智能家居。
2. **知识库**：新增智能家居种子知识（设备说明书、舒适规则、场景规则、安全规则），可经现有文档上传链路入库。
3. **意图关键词**：开/关灯、风扇、温度、湿度、睡眠模式、离家等路由到家居专家。
4. **工具注册**：`get_all_tools()` 挂载家居固定工具，同时保留通用 RAG 检索工具；任何设备控制都必须经过 `device_tools.py`。

## 6. 安全规则（第一版）

| 规则 | 行为 |
|---|---|
| 未注册设备 | 拒绝 |
| 设备离线 | 拒绝 |
| 非白名单动作 | 拒绝 |
| 命令过期 | 拒绝且不改状态 |
| 重复 request_id | 返回首次回执（幂等） |
| 睡眠模式关灯 | 允许 |
| 任意 Topic / GPIO | 永不暴露给 Agent |

## 7. 实施顺序

1. 扩展模型与安全规则
2. 设备服务与默认设备
3. 设备工具 + Agent 能力配置
4. MQTT 适配器
5. FastAPI 路由
6. ESP32 固件与联调说明
7. 单元测试与文档更新

## 8. 验收口径

- 无硬件：模拟适配器可完成状态查询、开/关灯风扇、睡眠模式、非法指令拦截。
- 有 Broker：MQTT 适配器可发布命令并等待 `ack`，超时返回失败原因。
- 有 ESP32：局域网内传感器上报 + LED/风扇回执闭环。
- 原有 RAG / 多轮会话接口不回归。
