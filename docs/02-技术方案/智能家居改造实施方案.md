# 智能家居改造实施方案

## 1. 改造原则

1. 保留 RAG、Agent 调度、多轮会话、认证、审计和租户隔离等通用基座；
2. 智能家居是当前唯一业务领域，设备控制统一经过固定工具和 `DeviceService`；
3. `simulated` 与 `mqtt` 适配器共用领域模型、命令、回执和安全规则；
4. 只支持版本三定义的传感器、执行器、手动/自动模式和 normal/sleep/away 场景预设；不恢复窗户或光照能力。

## 2. 目标架构

```text
Vue / APP / 按键 / 密码 / IC 卡
            ↓
FastAPI Home API + Agent 固定工具
            ↓
DeviceService + EnvironmentMonitor + 安全校验
            ↓
SimulatedAdapter 或 MQTT/Gizwits Adapter
            ↓
ESP8266 → STM32F103C8T6 → 传感器、OLED、低压执行器
```

## 3. 软件模块

| 模块 | 路径 | 当前职责 |
|---|---|---|
| 领域模型 | `app/home_automation/device_models.py` | 传感器、设备、阈值、门锁和回执模型 |
| 默认注册 | `app/home_automation/default_devices.py` | 五类传感器和五类设备 |
| 环境监测 | `app/home_automation/environment_monitor.py` | 质量、阈值、报警和自动动作判定 |
| 设备服务 | `app/home_automation/device_service.py` | 注册、状态、手动控制、自动联动和门锁安全链路 |
| 固定工具 | `app/home_automation/device_tools.py` | Agent 可用的查询、阈值、模式、执行器和门锁工具 |
| 适配器 | `app/home_automation/simulated_device.py`、`mqtt_adapter.py` | 模拟或受控协议执行 |
| API | `app/api/v1/endpoints/home_devices.py` | `/api/v1/home` REST 接口 |
| 前端 | `rag_frontend/src/api/home.ts`、`HomeDevicesView.vue` | 环境、模式、执行器、报警和门锁控制台 |

## 4. 自动规则

| 输入条件 | 固定动作 |
|---|---|
| 温度 > `temperature_max` | 风扇 ON + 蜂鸣器 ON |
| 烟雾 > `smoke_max` | 风扇 ON + 蜂鸣器 ON |
| 火焰 = 1 | 水泵 ON + 蜂鸣器 ON |
| 有人 = 1 | LED ON |
| 湿度 > `humidity_max` | 报警记录；暂不自动启动执行器 |

上述动作只有在 `automatic` 模式且传感器有效时执行。`manual` 模式只接受按键或 APP 的明确指令。

## 5. 实施阶段

### 阶段一：软件模拟闭环（已完成）

- 传感器/设备注册和统一状态模型；
- LED、风扇、水泵、蜂鸣器固定工具和 API；
- 手动/自动模式与三类阈值；
- 自动联动、报警、MQTT ack 校验和门锁安全绕过拦截；
- 前端控制台和知识种子对齐版本三。

### 阶段二：STM32 本地固件（待执行）

- 采集温湿度、烟雾、火焰、有人状态；
- OLED 刷新数据、模式、设备和报警状态；
- 按键去抖、手动控制、模式切换和阈值设置；
- 对密码、IC 卡和舵机门锁实现认证与状态机。

### 阶段三：ESP8266/机智云联调（待执行）

- 固件、UART、电平和供电确认；
- 机智云数据点与内部固定模型映射；
- telemetry、availability、state/ack 和 request_id 幂等；
- APP 查看数据、阈值调整和远程控制验收。

## 6. 验收口径

- 软件模拟回归必须通过后端家居、安全、MQTT、API、Agent 路由测试；
- 前端必须通过 `npm run build`，并能展示手动/自动模式和三种场景预设；
- 硬件验收必须单独记录 Broker、机智云产品/数据点、ESP8266 固件、STM32 固件、板卡和接线版本；
- 任何阶段都不得宣称模拟测试等于真实 OLED、按键、密码/IC 卡或云平台联调完成。
