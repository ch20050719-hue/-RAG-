# 智能家居模式与安全规则（版本三知识种子）

## 控制模式

### 手动模式（manual）

- 按键或 APP 发起设备控制。
- 支持风扇、LED、舵机门锁和喷淋水泵。
- 系统继续采集和显示环境数据。
- 门锁仍必须完成密码、IC 卡或 APP 授权。

### 自动模式（automatic）

| 条件 | 动作 | 报警 |
|---|---|---|
| 温度超过上限 | 开启风扇 | 蜂鸣器 |
| 烟雾超过上限 | 开启风扇 | 蜂鸣器 |
| 检测到火焰 | 开启喷淋水泵 | 蜂鸣器 |
| 检测到有人 | 开启 LED | 无 |

自动动作必须经过连续采样确认、设备类型校验、在线校验、TTL、幂等和执行回执校验。

## 场景预设

场景预设与手动/自动主控制模式是两层概念：

| 场景 | 固定动作 |
|---|---|
| `normal` 正常 | 选择正常工作基线，不隐式改变设备状态 |
| `sleep` 睡眠 | 关闭 LED，并在门磁为 closed 时尝试反锁 |
| `away` 离家 | 关闭 LED、关闭风扇，并在门磁为 closed 时尝试锁门 |

场景执行必须返回逐设备结果；门磁、在线状态、TTL 或 ack 失败时，场景只能返回 `partial_failed`/`failed`，不得伪报成功。场景不会切换 `manual`/`automatic`，也不会绕过门锁专用控制链路。

场景对应的人工工具白名单由后端强制执行：

| 场景 | 允许人工控制 |
|---|---|
| `normal` | LED、风扇、水泵、蜂鸣器、阈值、手动/自动模式、门锁 |
| `sleep` | LED、风扇、蜂鸣器、门锁 |
| `away` | 水泵、蜂鸣器、门锁 |

三个场景都保留环境读取、设备状态查询、场景切换和 automatic 安全联动。密码、IC 卡和 APP 都可作为门锁认证来源，但不能绕过门锁专用安全服务；前端隐藏工具不等于授权。

## 安全红线

1. 禁止输出 MQTT Topic、GPIO 编号、寄存器或原始底层指令；
2. 禁止控制未注册设备；
3. 禁止在设备离线时声称“已打开/已关闭”；
4. 禁止接受任意自定义动作名；
5. 命令必须携带 `request_id` 并等待回执；
6. 门锁不得通过通用设备 `on/off` 接口控制；
7. MQ-2 仅用于实验模拟量展示，不得宣称消防级报警能力；
8. LED、风扇、水泵和舵机使用低压供电，不接入 220V 市电。
