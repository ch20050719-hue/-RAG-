## 1. 项目结论与范围调整

本项目当前只交付一条实物控制链路：

```text
机智云 APP ⇄ 机智云云端 ⇄ ESP8266 Wi-Fi 模块 ⇄ STM32F103C8T6 ⇄ 桌面模型设备
```

不以网页控制台、模拟器、RAG/知识问答或 Agent 对话作为产品操作入口。机智云 APP 的固定设备控件直接发送已定义的数据点；STM32 负责校验数据点并驱动对应的低压执行器。

| 旧代码或旧文档内容 | 当前决定 |
|---|---|
| 水泵/喷淋泵 | 项目没有水泵。取消水泵设备、界面控件、数据点和自动联动。旧后端中的 `sprinkler_pump` 是模拟配置，不代表实物。 |
| 独立火焰检测 | 不做独立火焰传感器、火焰数据点或火焰联动。项目保留烟雾检测，不把烟雾读数改称为火焰检测。 |
| “有人”检测 | 没有该传感器驱动，不纳入目标；移除模拟注册、界面显示和相关联动。 |
| 网页家居演示模块 | 正式退出本项目交付范围。后续操作和验收以机智云 APP 控制真实模型为准，不再要求启动网页、操作网页模拟设备或维护家居控制台。 |
| RAG/知识问答/自然语言设备控制 | 不属于当前控制系统目标；不得让 APP 控制依赖 RAG、Agent 或知识库。仓库其他通用模块不因此自动删除，但不得作为本项目功能入口。 |
| 场景、网页趋势图、定时任务等扩展演示 | 不列入当前验收；除非用户之后重新确认，不扩展实现。 |

## 3. 功能需求与操作流程

### 3.1 机智云 APP 必需功能

APP 只提供固定控件，不提供自由 Topic、GPIO、任意命令或自然语言操作。

| APP 控件 | 发送值 | STM32 行为 | APP 预期反馈 |
|---|---|---|---|
| LED | 开 / 关 | 设置 LED 输出 | 显示最新设备状态或“命令未确认” |
| 风扇 | 开 / 关 | 设置低压风扇驱动输出 | 显示最新设备状态或“命令未确认” |
| 窗户 | 打开 / 关闭 | 驱动 28BYJ 到对应方向/位置 | 显示固件报告的目标状态；没有限位反馈时不得宣称窗户已到位 |
| 舵机锁门 | 上锁 / 解锁（是否开放远程解锁须在 APP 账号和模型安全方案中确认） | 通过 MG90S 驱动完成预定义舵机动作 | 显示命令回执；没有门磁/锁舌反馈时不得宣称门体已实际上锁或解锁 |

最低限度的状态反馈包括：机智云设备在线/离线、最后收到的设备状态、命令是否被固件接受。只有固件执行结果或传感反馈才能作为“执行完成”；云端收到 APP 命令、SDK 收到数据点，都不能单独证明机械动作已到位。

### 3.2 环境数据的最小范围

环境采集不是额外的网页演示功能。若当前论文和实物方案保留环境感知，APP 只需展示本机已有且确认接线的温度、湿度和烟雾读数，用于观察模型状态；不引入独立火焰或“有人”数据项。原始烟雾 ADC 值须标明为原始量，完成传感器标定后再决定单位和报警阈值。

网页历史曲线、复杂报警中心、睡眠/离家场景和定时任务不属于当前 APP 直控的最低验收范围。

### 3.3 用户操作闭环

1. 将 STM32 固件、ESP8266 模块、机智云产品物模型和 APP 设备页面配置为同一产品与数据点版本。
2. 模型上电，ESP8266 连入配置的 Wi-Fi 并接入机智云；APP 显示设备在线。未在线时先处理配网/模块连接，不应显示可执行成功。
3. 用户在 APP 选择一个固定控件和目标状态，例如“LED 开”或“窗户关闭”。
4. 机智云下发对应数据点；STM32 的 MCU SDK 解析事件，检查数据点取值和允许动作，再调用现有硬件驱动。
5. STM32 更新当前状态并通过 SDK 上报；APP 刷新为固件确认的状态。超时、无效数据点、模块离线或驱动失败时，APP 保持“未确认/失败”，不能乐观地永久切换成成功状态。
6. 用户可再次发送同一状态；重复命令应保持安全，不得导致电机持续运行或重复执行不可逆动作。

### 3.4 明确不做的交互

- 不通过浏览器网页或模拟器操作模型。
- 不加入知识问答、RAG、聊天 Agent、语音助手或大模型生成式设备指令。
- 不增加水泵、火焰传感器、“有人”传感器及其模拟值。
- 不扩展场景商城、定时计划、额外仪表盘或不在硬件清单中的设备。
- 本次交接将自动模式、远程阈值配置视为现存固件功能，不作为机智云 APP 必须验收项；如要保留为正式安全功能，需先明确规则、优先级和失联时行为。

## 4. 机智云对接与通信规范

### 4.1 分层和责任边界

| 层 | 责任 |
|---|---|
| 机智云 APP | 展示设备控件、发送固定数据点、显示在线状态和设备上报状态。 |
| 机智云云端 | 负责 APP 与已绑定设备间的数据点路由、设备绑定和在线状态服务。 |
| ESP8266 | 使用已配置的机智云兼容固件/协议连接 Wi-Fi 和机智云，并通过 UART 与 STM32 交互。固件类型和配网流程尚待实物确认。 |
| STM32 MCU SDK | 接收并解析机智云协议帧、产生数据点事件、报告传感器和执行器状态。 |
| 产品适配层 | 在 `gizwitsEventProcess()` 中把允许的数据点映射到固定驱动函数；在 `userHandle()` 中采集和填充上报数据。不得把网络数据直接当 GPIO 编号或任意函数调用。 |
| 外设驱动 | 只负责已确认的 LED、风扇、窗户步进电机和 MG90S 动作。网络协议不应散落到各驱动内部。 |

当前基本链路不需要网页 API、模拟适配器或另建 MQTT Broker。使用机智云 SDK 的场景，应遵照对应机智云产品物模型与设备模块协议；不要把旧网页模块的 MQTT topic/JSON 契约误当成机智云数据点协议。

### 4.2 当前固件接口基线

- `gizwits_product.h` 将 `MODULE_TYPE` 配置为 `0`（Wi-Fi 模块）。
- 综合工程在 `main()` 中调用 `uart2_init(9600)`、`gizwitsInit()`；USART2 使用 PA2/PA3。当前串口配置为 9600 baud、8 数据位、无校验、1 停止位、无硬件流控。实际 ESP8266 侧必须配置为一致参数，并核对电平和交叉接线。
- USART2 接收中断把收到的字节交给 `gizPutData()`；主循环调用 `userHandle()` 和 `gizwitsHandle()`。
- 机智云 SDK 已定义 APP→设备控制、读状态、状态应答、设备上报等协议动作码（例如 `0x11` 控制、`0x12` 读状态、`0x13` 应答、`0x14` 上报）。这些是 SDK 协议层定义，不应由 APP 使用者手工拼帧。
- 现有综合工程位于 [STM32_CGMCU.uvprojx](../../stm32/程序/USER/STM32_CGMCU.uvprojx)，主循环位于 [main.c](../../stm32/程序/USER/main.c)，机智云事件和数据点映射位于 [gizwits_product.c](../../stm32/程序/Gizwits/gizwits_product.c)，数据点定义位于 [gizwits_protocol.h](../../stm32/程序/Gizwits/gizwits_protocol.h)。

### 4.3 数据点契约

以下是 APP 与 STM32 之间的逻辑契约。最终名称、读写权限、取值范围、单位和比例系数必须与机智云控制台生成的物模型一致；若物模型修改，须同步重新核对/生成 SDK 定义，不得只改 C 文件中的变量名。

| 类别 | 目标语义 | 类型与取值 | 当前固件情况 |
|---|---|---|---|
| 控制命令 | LED、风扇开关 | 布尔值：0 关、1 开 | 已有 `valueLight`、`valueFan` 和事件枚举；事件映射需要修正和实机验证。 |
| 控制命令 | 窗户开/关 | 固定枚举或布尔目标：0 关、1 开 | 已有 `valueCurtain`；事件回调和主循环标志值不一致，当前不能认定 APP 已能驱动窗户。 |
| 控制命令 | 舵机锁门 | 固定枚举：上锁/解锁；限制授权用户 | 当前 SDK 没有门锁 APP 数据点/事件，需要和机智云物模型一起新增。 |
| 设备状态 | LED、风扇、窗户、门锁目标状态 | 与命令类型匹配 | LED/风扇/窗户可在 `userHandle()` 中填充；锁门状态需新增。无位置反馈时只上报目标/命令状态。 |
| 环境上报 | 温度、湿度 | 数值；单位 °C、% | 已有 DHT11 采集和 `valuetemp`、`valuehumi` 字段。 |
| 环境上报 | 烟雾原始读数 | 无符号数值；暂标 raw/ADC count | 已有 `valueSmmmoke` 字段，上限定义为 2000；须确认 ADC 实测范围并校正物模型。 |
| 可选上报 | 光照原始/换算读数 | 数值；必须统一比例和单位 | 当前有 `valueLight_intensity` 和 ADC 通道 5；是否纳入 APP 由实物和当前需求确认。 |

旧 SDK 中已有手动/自动模式和温湿度/光照/烟雾阈值数据点，但本次目标不要求远程调阈值或模式。若后续保留，须先修正事件映射、取值比例，并补上需求与验收，不要沿用当前错误处理。

### 4.4 控制可靠性和安全规则

- APP 只发送产品物模型中允许的固定数据点和值；STM32 对枚举范围进行校验，未知值不驱动硬件。
- 输出控制统一经过产品适配层和现有驱动接口；禁止通过数据点接受任意 GPIO、PWM 脉宽、舵机角度或步进脉冲数。
- LED/风扇重复设置为同一目标状态应保持幂等；步进电机和舵机动作需有动作时限、运行中命令处理规则及看门狗保护。
- 门锁类命令应使用专用事件，不与普通开关数据点混用。只在低压桌面模型验证，不连接真实住宅门锁。
- SDK/串口收到命令不等于执行完成。需要确认 SDK 可用的状态上报/应答路径，APP 以设备回报状态为准；断网、模块重启和 MCU 重启后须重新同步状态。
- 日志不得打印 Wi-Fi 密码、机智云密钥、产品密钥或用户凭证。

## 6. 当前验收标准

只有完成下列实物流程并留下版本与结果记录，才能称为“机智云 APP 远程控制完成”：

1. APP、机智云产品物模型、ESP8266 固件与 STM32 SDK 使用同一数据点定义。
2. 设备能够稳定上云并在 APP 中显示在线；断开 Wi-Fi/模块后能显示离线或控制失败。
3. LED、风扇、窗户分别能从 APP 发出开/关命令，实物反应与控件一致；重复发送、快速切换和非法值不会产生危险动作。
4. APP 最终状态来自 STM32 回报；云端接收或串口收到命令不能冒充机械到位。
5. MG90S 锁门命令具有单独的数据点和受限映射；没有门磁/位置/锁舌反馈时，界面明确显示为“命令/目标状态”，不能宣称物理锁定已确认。
6. 温湿度和烟雾读数按确认的采样周期上报；烟雾量标注 raw，除非完成现场标定。
7. 实物联调记录写明：STM32 板卡与固件版本、ESP8266 型号/固件、串口参数、机智云产品/物模型版本、接线和供电、APP 操作步骤及通过/失败结果。凭证和密钥不写入记录。

## 7. 推荐实施顺序

1. **冻结物模型：**在机智云控制台确认产品、设备、命令/状态/传感器数据点、类型、取值、单位、读写权限；导出或记录版本。
2. **清理范围：**从智能家居产品配置与交付界面清除水泵、火焰、“有人”、网页模拟控制、RAG/Agent 入口及不需要的演示功能；保留与本目标无关的通用代码时注明其不属于项目。
3. **修固件收发：**先修复 UART 发送循环和接收/发送边界，再核对协议 SDK 版本与 ESP8266 侧配置。
4. **修事件映射：**按物模型逐项核对 LED、风扇、窗户的事件、驱动输出和状态回报；新增门锁固定事件与安全限制。
5. **稳定采集：**把 DHT11/ADC 采样从 OLED 页面刷新逻辑中分离，使机智云上报不依赖当前屏幕页面；加入合理采样间隔和无效读数处理。
6. **逐设备台架验证：**先单独测 UART 和数据点，再测 LED/风扇，再测步进电机，最后测舵机。确认驱动电源独立、共地和 GPIO 电平。
7. **APP 端到端验收：**按第 6 节逐条操作；断网、重启、重复命令、非法值和响应超时都要验证并记录。
8. **同步事实源：**完成清理/联调后，再更新硬件清单、架构决策、远程控制开发文档、根 README 和 changelog，保证它们不再保留互相冲突的旧能力描述。

## 8. 遗留问题与后续建议

### 8.1 已定位的固件问题

1. `gizwits_product.c` 的 `uartWrite()` 发送循环使用 `i--`，起始索引为 0 且 `i` 是无符号类型，正常数据长度下循环只发送首字节后即回绕退出，造成机智云协议帧截断；需改正并进行串口实测。
2. 湿度、光照和烟雾阈值事件目前误写入温度阈值变量；这些阈值功能不是本次验收项，若保留则逐个修复。
3. 窗帘事件回调将标志设为 2，而主循环只在标志为 1 时执行；机智云 APP 窗户命令目前不能据源码判断为有效。
4. LED/风扇事件中的模式判断和 `USB_ON/OFF` 通道参数不一致，需要依据板卡接线与目标行为重新核实，不能直接把现有映射当作正确。
5. 当前机智云数据点没有 MG90S 门锁控制事件；舵机仅有驱动和串口命令路径。
6. DHT11、烟雾和光照采集挂在 OLED 主页面 `Menu1()`；切到其他菜单时数据可能不刷新，需改为固定周期采样。

### 8.2 硬件与协议待确认

- PCB 图片只标有 WiFi 区域，未提供可核验的无线模块型号、原理图和引脚/net 名称；须确认 ESP8266 是否为板载器件、具体型号、机智云兼容固件/协议、配网方式及控制台物模型版本。
- PA2/PA3 与 ESP8266 TX/RX 的接线方向、共地、3.3 V 电平和供电能力；当前固件串口为 9600、8N1。
- 烟雾传感器实物型号、ADC 前端电压范围、预热要求和阈值标定方法；未经确认不把原始 ADC 换算成 ppm。
- 窗户和舵机机构是否有位置/限位/门磁反馈；若没有，APP 状态只能表示命令目标。
- 远程解锁是否开放、APP 账户授权要求和失联时默认行为。
- 光照是否保留为 APP 数据点；自动模式和远程阈值是否属于最终系统需求。
- 论文方向是否仍要求大模型研究内容。当前交接仅确认控制链路不依赖 RAG/Agent；不应自行把聊天控制加入产品。

### 8.3 旧文档冲突

此前的交接说明、架构决策、硬件采购清单、远程控制文档、根 `agents.md` 及历史 changelog 中有水泵、火焰、人员检测、网页控制台、模拟器、RAG/Agent、MQTT 设备桥和复杂场景等不同表述。自本交接日期起，智能家居交付范围以本文件记录的最新用户决定为准。根 `agents.md` 中“后端固定工具、模拟适配器、MQTT/JSON/QoS1 受控桥”的旧控制链路不适用于当前机智云 APP 直控实物方向；低压桌面模型、安全用电等约束仍继续遵守。后续应按第 7 节第 8 步同步清理文档，不能引用旧内容扩大硬件或论文功能范围。

## 9. 交接结语

后续智能体接手时，先从综合 Keil 工程中的机智云 SDK、数据点事件和 USART2 链路开始；优先保证“机智云 APP 发出固定命令 → STM32 正确驱动实物 → STM32 回报状态 → APP 显示真实回报”这一闭环。除这一闭环和必要的温湿度/烟雾状态上报外，不新增网页演示、模拟家居、RAG、Agent、火焰/有人检测或水泵功能。
