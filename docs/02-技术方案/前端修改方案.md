# 智能家居前端说明

## 1. 目标

前端围绕智能家居单一模块提供两类入口：自然语言对话和设备控制台。对话入口继续复用 RAG、Agent、多轮会话和 SSE；控制台调用后端 `/api/v1/home`，不直连 MQTT 或设备。

## 2. 页面与路由

| 页面 | 路由 | 用途 |
|---|---|---|
| 智能家居对话 | `/chat` | 查询设备、环境和家居规则，执行固定工具 |
| 多 Agent 对话 | `/multi-agent` | 展示意图、检索、环境和控制阶段 |
| 设备控制台 | `/home-devices` | 查看设备/环境、控制灯风扇、执行场景 |
| 知识库 | `/knowledge` | 管理设备说明、环境规则和场景知识 |
| 检索 | `/search` | 查看检索结果、引用和来源 |
| 设置 | `/settings` | 管理模型、偏好和系统配置 |

## 3. 设备 API 客户端

实现位置：`src/api/home.ts`。所有请求沿用现有认证、租户和错误处理机制。

```text
GET  /api/v1/home/devices
GET  /api/v1/home/devices/{device_id}
POST /api/v1/home/devices/{device_id}/state
GET  /api/v1/home/environment?room=study
POST /api/v1/home/scenarios
```

控制请求只提交设备 ID、允许状态和可选 `request_id`。安全校验、超时、ack 和失败原因由后端负责，前端展示 `accepted`、`state`、`message` 和 `blocked_reason`。

## 4. 交互流程

```text
加载设备列表
  → 读取在线状态和环境快照
  → 用户发起控制或场景请求
  → 显示“等待设备回执”
  → accepted=true 展示最新状态
  → accepted=false 展示阻断原因和建议
```

前端不把命令发送成功当作设备执行成功，只有后端确认 ack 后才显示成功。

## 5. 文案与安全

- 页面标题、菜单、空状态和错误提示统一使用智能家居词汇；
- 不展示 MQTT 密码、底层客户端对象、任意 Topic 或 GPIO；
- 对控制按钮增加在线状态和二次确认提示；
- `blocked_reason` 使用用户可理解的安全说明，不展示内部堆栈；
- 仅将低压 LED、5V 风扇和已注册传感器作为演示设备。

## 6. 验证

```powershell
npm run build
```

构建通过后，再使用模拟适配器验证设备列表、单设备控制、场景执行、离线拦截和重复请求展示。真实 MQTT 联调按 [MQTT 联调说明](MQTT联调说明.md) 执行。
