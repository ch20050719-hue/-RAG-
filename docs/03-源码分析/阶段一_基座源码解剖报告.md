# 智能家居基座源码说明

## 1. 代码分层

```text
rag_backend/app/
├── api/                  FastAPI 路由、认证依赖和 SSE 接口
├── services/             RAG、会话、缓存和基础服务
├── langgraph/            多阶段 Agent 工作流编排
├── agent_framework/      ReAct/Plan/Reflect、工具管理和多轮循环
├── multi_agent_system/   专家 Agent、上下文和结果汇总
└── home_automation/      智能家居设备领域模块
```

## 2. 保留的基座能力

- 文档解析、切块、Embedding、向量/关键词/混合检索和来源引用；
- 普通对话、SSE 流式输出、任务状态、会话历史和上下文恢复；
- Agent 意图路由、工具调用、并行调度、结果聚合和质量检查；
- 用户认证、租户隔离、权限、审计、限流和安全事件。

这些能力的公共接口继续作为智能家居的通用基础，不在业务层增加第二套实现。

## 3. 家居模块接入点

| 接入点 | 说明 |
|---|---|
| `home_automation/device_models.py` | 设备、传感器、状态、命令和场景类型 |
| `home_automation/device_service.py` | 设备注册、查询、控制、场景和适配器调用 |
| `home_automation/safety_rules.py` | 设备类型、在线、动作、TTL、幂等和状态校验 |
| `home_automation/device_tools.py` | Agent 唯一可调用的固定设备工具 |
| `home_automation/adapters.py` | 设备适配器抽象 |
| `home_automation/simulated_device.py` | 本地模拟执行和 ack |
| `home_automation/mqtt_adapter.py` | Broker 连接、QoS 1 发布和 ack |
| `api/v1/endpoints/home_devices.py` | `/api/v1/home` 查询、控制和场景 API |

## 4. 请求执行顺序

```text
Chat / Multi-Agent
  → home intent routing
  → RAG rule retrieval
  → fixed device tool
  → DeviceService
  → SafetyRules
  → adapter.execute
  → ack/state result
```

安全规则位于适配器之前，适配器只接收已通过校验的结构化命令。模型不会获得 Topic、GPIO 或凭据。

## 5. 前端接入

`rag_frontend/src/api/home.ts` 调用 `/api/v1/home`，`HomeDevicesView.vue` 展示设备状态、环境快照、场景和控制结果。设备页不实现 MQTT 客户端，避免绕过后端安全控制。

## 6. 已知启动依赖

完整 FastAPI 应用需要按 `rag_backend/requirements.txt` 安装依赖。当前开发环境的虚拟环境缺少 `minio`，因此完整应用导入需补齐依赖后复测；家居单元测试使用模拟适配器，不依赖在线基础设施。
