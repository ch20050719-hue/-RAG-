## 2026-10-13 串口异常恢复与模式切换

当前配套固件保持 9600 8N1、STM32 PB10 TX/PB11 RX、ESP32 IO17 TX/IO18 RX，屏幕保持 128×160。橙色 PB11 接 IO17，黄色 PB10 接 IO18，两端共地。两块板须配套更新；以下验证是主机模拟和构建验证，尚未烧录或完成实物验收。

### 接收异常与控制顺序

- STM32 USART1/3 先读取 SR，再读取 DR 清除接收错误；处理 ORE、FE、NE、PE，包括 ORE 存在但 RXNE 未置位的情况。错误字节不参与组帧，仅丢弃未完成帧，保留完整命令队列。USART2 继续使用原机智云入口。
- `USART_GetControlDiagnostics(1/3, &snapshot)` 提供原子诊断快照：正常接收字节、溢出、帧错、噪声、奇偶错、队满、过期和排队数量。计数到 UINT16_MAX 饱和；不增加串口报文或云端工具。
- ESP32 使用容量 16 的 UART 事件队列和单一接收任务。FIFO 溢出、缓冲区满、帧错、奇偶错、BREAK 或数据读取异常时，重置半帧、使环境缓存无效，并清理损坏输入和过期事件；flush 失败每 100ms 重试，成功前不解析数据。等待事件超时后发现残留字节时，按丢通知处理并恢复。
- UART 错误为事件级通知，不能逐字节定位所有损坏数据；遥测仍以完整帧校验和 3000ms 有效期保护查询。异常恢复后须收到新的合法遥测才能恢复有效读数。
- STM32 在命令处理前后同步模式变化，自动转手动的清理不再被配网提示延后。后续开灯、开风扇、开窗命令不会被这次清理覆盖；开关窗指令清除相反的待执行标志。睡眠下发关窗目标，离家不主动改变窗户，单设备原始命令仍不自动切模式。
- ESP32 单设备请求仍先发手动帧，再发动作帧；第一帧发送完成后直接发送第二帧，取消固定 350ms 等待，每次请求结束后的 100ms 节流保留。首帧写入或发送完成等待失败，不发送动作帧。此行为依赖本次 STM32 模式清理修复，不适用于只升级 ESP32、保留旧 STM32 的组合。
- 同源命令按 FIFO 顺序执行；多控制来源交错仍不是原子事务。本次没有增加 ACK、重试或新协议，工具返回入队结果，不能代表执行确认或机械到位。

## 2026-10-11 聆听超时

小智应用增加无人说话自动待机：唤醒后或回复播放完毕后，连续 8 秒未检测到语音，关闭音频会话并恢复唤醒词待机。8 秒内继续说话可保持连续对话；此判断针对语音活动，不要求是设备控制指令。手动按键录音不受这个计时限制。

收到语音活动或非空识别文本后，暂停空闲计时，等待服务端回复；回复开始和播放期间不触发 8 秒超时。`tts stop` 后仍须等待本地播放队列排空。若声音被误检或服务端没有回复，另有 60 秒响应等待上限，防止永久聆听；持续说话会刷新该上限。无 VAD 的音频引擎不启用本功能，当前 S3 配置启用了音频处理器。

实现位于小智应用 `main/application.cc`、`main/application.h`、`main/conversation_timeout.h`，参数为 `kSilenceUs` 和 `kResponseWaitUs`。复用已有状态机、VAD、播放排空检测和音频通道关闭接口，不修改 STM32 协议。参考[上游无人说话超时讨论](https://github.com/78/xiaozhi-esp32/discussions/1547)与[官方语音协议](https://github.com/78/xiaozhi-esp32/blob/main/docs/websocket_zh.md)；本实现额外区分等待回复和本地播放尾音。

## 命令与模式

帧为四个原始字节 `F4 06 命令 FB`，串口助手应选择 HEX 发送。

| 功能 | 命令 |
|---|---|
| 灯开 / 关 | 01 / 02 |
| 风扇开 / 关 | 03 / 04 |
| 窗户开 / 关 | 05 / 06 |
| 手动 / 自动 | 07 / 08 |
| 门开 / 关 | 09 / 0A |
| 睡眠 / 离家 | 0B / 0C |
| 起床 | 0D |

ESP32 单设备控制先发手动命令，等待该帧发送完成后直接发送动作；请求结束后节流 100ms。此顺序依赖 2026-10-13 配套 STM32 固件。模式工具只发该模式命令。
STM32 从自动切手动时会关灯、关风扇、请求关窗并停蜂鸣器，随后执行指定单设备动作。
睡眠：手动、风扇开、灯关、门关并下发关窗目标；离家：手动、风扇关、灯关、门关，不改变窗户。起床：手动、灯开、风扇关、门开，回到正常场景并保持窗户目标。普通手动与正常场景不隐式执行起床动作。窗户依靠软件步数估算，已关闭时不会重复转动，不代表有实物位置反馈。
手动、自动及单设备命令清除场景标记。自动模式按既有传感器阈值逻辑运行。
