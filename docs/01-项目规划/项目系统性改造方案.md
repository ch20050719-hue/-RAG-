# 智能家居项目系统性改造方案

## 1. 目标与范围

将现有 RAG 应用收敛为智能家居单一业务模块：用户可以询问设备和环境，也可以在安全边界内控制低压灯/风扇并执行预置场景。

保留以下通用能力和接口语义：

- RAG 检索、知识库文档处理和来源追溯；
- Agent 意图识别、任务编排、固定工具调用和结果汇总；
- 多轮会话、上下文管理、SSE 流式输出和异步任务恢复；
- 认证、租户隔离、权限、审计、限流和安全监控。

旧财税、税务、法务业务不在当前范围内，不再作为代码入口、知识种子、提示词、配置或前端菜单维护。

## 2. 总体架构

```text
Vue 控制台 / RAG 对话
          │ HTTP / SSE
          ▼
FastAPI
  ├─ 会话与多轮上下文
  ├─ 智能家居意图 → RAG → Agent 编排
  └─ /api/v1/home
          │
          ▼
固定设备工具 → DeviceService → SafetyRules
                              │
                    ┌─────────┴─────────┐
                    ▼                   ▼
             模拟设备适配器       MQTT 适配器 → ESP32
```

控制面与设备面隔离：模型只看到固定工具和结构化结果，服务端负责设备注册表、命令校验、适配器选择和回执处理。

## 3. 模块设计

| 模块 | 代码位置 | 责任 |
|---|---|---|
| 设备模型 | `app/home_automation/device_models.py` | 设备、状态、传感器、场景和命令结果模型 |
| 设备注册 | `app/home_automation/default_devices.py` | 桌面原型默认灯、风扇和传感器 |
| 设备服务 | `app/home_automation/device_service.py` | 查询、控制、场景和适配器调用 |
| 安全规则 | `app/home_automation/safety_rules.py` | 白名单、类型、在线、状态、TTL、幂等校验 |
| 固定工具 | `app/home_automation/device_tools.py` | Agent 可调用的设备工具唯一入口 |
| MQTT | `app/home_automation/mqtt_adapter.py` | QoS 1 命令、ack、telemetry 和 availability |
| API | `app/api/v1/endpoints/home_devices.py` | 设备列表、状态、环境和场景 REST API |
| ESP32 | `esp32/esp32_home_node` | LED、5V 风扇和传感器桌面原型 |

## 4. RAG 与 Agent 领域改造

知识库种子限定为：设备说明、传感器字段、环境舒适度、场景执行条件、操作安全规则和故障排查。现有文档上传、切块、向量化、检索和引用链路继续复用。

意图路由至少覆盖：

```text
设备查询 | 环境查询 | 灯控制 | 风扇控制 | 睡眠场景 | 离家场景 | 观影场景 | 家居知识问答
```

复杂请求仍经过原有 Agent 编排和多轮会话流程；涉及真实控制时，只有固定工具可以产生设备命令。

## 5. 安全控制面

控制请求必须满足：

1. 设备已注册且属于允许的设备类型；
2. 设备在线，且目标动作属于白名单；
3. 命令状态有效、参数合法且未超过 TTL；
4. `request_id` 未被重复使用，重复请求返回首次结果；
5. MQTT ack 与目标设备、request_id 匹配，超时或否定 ack 视为失败。

以下内容永不暴露给模型或普通前端：任意 Topic、GPIO、底层 MQTT 客户端对象、设备凭据和 Broker 密码。

## 6. API 契约

前缀：`/api/v1/home`。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/devices` | 查询设备列表 |
| GET | `/devices/{device_id}` | 查询单个设备 |
| POST | `/devices/{device_id}/state` | 执行 `on/off` 控制 |
| GET | `/environment?room=study` | 查询环境快照 |
| POST | `/scenarios` | 执行 `sleep/away/movie` |

## 7. 实施与验收

实施顺序：领域配置与知识种子 → 设备模型/服务 → 安全规则 → 固定工具 → 模拟适配器 → MQTT → API/前端 → ESP32 → 回归测试。

验收标准：

- 模拟模式完成状态查询、灯/风扇控制、场景执行和非法命令拦截；
- MQTT 模式发布 QoS 1 结构化命令，并能按 request_id 等待 ack；
- ESP32 完成低压 LED/5V 风扇控制和传感器回报；
- RAG、Agent 调度和多轮会话回归不破坏；
- 后端家居与安全测试、前端构建和 `git diff --check` 通过。

参考实现遵循 [Paho MQTT Python Client](https://eclipse.dev/paho/files/paho.mqtt.python/html/client.html)、[OASIS MQTT 3.1.1](https://docs.oasis-open.org/mqtt/mqtt/v3.1.1/mqtt-v3.1.1.html) 和 [ESP-IDF MQTT](https://docs.espressif.com/projects/esp-idf/en/stable/esp32/api-reference/protocols/mqtt.html) 的公开契约。
