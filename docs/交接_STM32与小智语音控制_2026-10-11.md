## 5. 关键技术与控制协议

### 接线

| ESP32 | STM32F103C8T6 |
|---|---|
| IO17 TX → | PB11 / USART3_RX |
| IO18 RX ← | PB10 / USART3_TX |
| GND | GND |

串口为 9600、8N1、3.3V 逻辑。USART1 PA9 TX / PA10 RX 保留离线语音；USART2 PA2 TX / PA3 RX 保留机智云。当前 USART3 没有执行 ACK 或传感器回传协议。

### 指令与模式

每帧为四个原始字节 `F4 06 命令 FB`，串口助手使用 HEX 发送。

| 功能 | 命令字 |
|---|---|
| 灯开／关 | 01／02 |
| 风扇开／关 | 03／04 |
| 窗户开／关 | 05／06 |
| 手动／自动 | 07／08 |
| 门开／关 | 09／0A |
| 睡眠／离家 | 0B／0C |

工具 `self.stm32.set_device(device, on)` 接受 `light/fan/window/door` 和布尔值；先发手动帧，等待 350ms，再发设备动作。`self.stm32.set_mode(mode)` 接受 `manual/auto/sleep/away`，只发送对应模式帧。请求之间另有 100ms 间隔；手动帧发送失败时不继续发送设备动作。

STM32 从自动切手动会关灯、关风扇、请求关窗并停蜂鸣器，再执行指定设备动作。这是现有模式切换行为，联调时要检查这些连带动作。睡眠为手动、风扇开、灯关、门关；离家为手动、风扇关、灯关、门关；两种场景均不改变窗户。手动、自动和单设备命令清除场景标记。

设备端 MCP 复用小智已有设备连接。回执仅说明“指令已加入串口发送队列，尚未确认 STM32 执行或设备到位”；用户此前提供的外部 MCP 接入点没有作为设备语音连接写入固件。

### 舵机

MG90S 使用 PA0 / TIM2_CH1，50Hz、20ms 周期、1µs 计数单位。动作输出期限为 1000ms；同目标重复请求不延长，反向请求重新计时，结束时保留完整脉冲再停低。

用户已确认交换开关门对应：开门 1000µs 向回收，关门 1600µs 向外转；两个端点仍待实物复测。上电保持无 PWM，不因门默认关闭而自动驱动。代码限定端点为 1000..2000µs 且不能相同，不能把脉宽直接写成已经校准的角度。

### ESP-IDF 环境恢复与构建

应用根目录是 `F:\esp\v6.0.2\esp-idf-2\xiaozhi-stm32`，在该目录执行 `idf.py`。在 `build` 子目录执行会找不到工程 `CMakeLists.txt`。

该应用使用 `esp-idf-2` 框架，已安装工具位于 `F:\Espressif\tools`。工具根变量 `IDF_TOOLS_PATH` 应为 `F:\Espressif`。旧 bootloader 缓存来自 `esp-idf-2`，混入 `F:\esp\v6.0.2\esp-idf` 会出现 CMake 源目录与缓存不一致错误。

在 PowerShell 中逐条执行：

```powershell
$env:IDF_TOOLS_PATH = 'F:\Espressif'
$env:IDF_PATH = 'F:\esp\v6.0.2\esp-idf-2'
```

| 容易再出现的问题 | 下次处理方式 |
|---|---|
